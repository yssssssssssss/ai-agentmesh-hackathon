# 适配 Zero 的超品通栏审核 Skill

本 Skill 用于 Zero / Relay 中的 `252 通栏静态视觉审核`。  
输入是一张候选通栏图，输出必须落到 Zero 画布里。

必须同时创建：

1. `{案例名}超品通栏审核标注图`
2. `{案例名}超品通栏审核问题清单`

不要只在聊天里回复。不要生成规则包。不要复述本 Skill。不要输出完整思考过程。

## 任务边界

只审核当前上传/引用/选中的这一张 252 静态超品通栏图。

如果没有收到候选通栏图，只收到规范文档、Skill 文件或历史案例，不要审核，回复：

```text
我还没有收到需要审核的通栏图片。请上传或引用一张候选 252 超品通栏图。
```

## 必须读取的知识

执行审核前，必须按需使用以下 reference。它们是本 Skill 的核心，不是可选补充：

- `references/审核规则.md`：252 通栏规范和具体审核项。
- `references/硬性软性判定.md`：硬性必改与软性优化的判定口径。
- `references/输出版式规范.md`：Zero 画布点位图和问题清单的输出版式。
- `references/案例校准知识.md`：用户校准过的案例判断经验。
- `references/案例炼化执行规则.md`：从历史案例和用户纠正中炼化出的执行口径，用于判断结构、对齐、关键承载色、商品突出度和误判边界。

## 输出硬性要求

必须在 Zero 画布中生成：

- 问题点位图：复制原通栏节点，在副本上叠加矢量标注。
- 问题清单：根据当前图片的问题重新填写，使用固定阅读型表格版式。

注意：

- 问题清单的“空调清单样式”只代表表格视觉版式，不代表审核内容模板。
- 每次审核的问题点、原因、修改方向都必须根据当前上传图片重新判断。
- 每条审核意见必须能在当前图片上找到对应的可见问题区域；找不到明确点位的问题不要输出。
- 先确定问题点位和编号，再生成问题清单；不要先写清单再随意画框。
- 不要套用空调案例、五粮液案例或任何历史案例里的问题内容。

## 禁止

- 不要 AI 生成、重绘、修图或替换原通栏。
- 不要使用 `batchGenerateIRelay`、`refIRelayUrl`、`editMode=true`。
- 不要使用 HTML 截图方式。
- 不要生成灰色占位图、空白图、相似图、新位图。
- 不要只输出文字、坐标或 Markdown 表格。
- 不要标注“未知问题”“疑似问题”“待确认问题”。
- 不要输出通过项、评分、规则 ID、完整推理过程。

## 审核流程

1. 确认当前输入是一张 252 静态超品通栏图。
2. 根据 `审核规则.md` 和 `硬性软性判定.md` 判断问题。
3. 对每个候选问题做图像证据校验：问题位置、原因和修改方向必须与图上框选区域一致。
4. 删除找不到明确图上证据、点位不清、原因与区域不对应的问题。
5. 只保留需要修改的问题，优先 P0/P1，再输出必要的 P2。
6. 根据 `输出版式规范.md` 创建点位图。
7. 根据 `输出版式规范.md` 创建问题清单。
8. 用 `案例校准知识.md` 和 `案例炼化执行规则.md` 做最终校准，避免误判、漏判和泛泛审美点评。

## 完成标准

- 标注图基于原图副本，而不是新图片。
- 标注框/圈是 Zero 矢量图形。
- 标注框清晰可见。
- 标注框/圈只使用描边，fill 必须为透明，不要加任何颜色填充。
- 每个标注框必须圈住该条问题实际发生的区域，不能框到无关区域。
- 编号大、居中、清楚。
- 每个标注编号在问题清单里有对应行。
- 问题清单每一行的“问题位置、原因、修改方向”必须和同编号标注框对应。
- 右上角组件区只按画布右上角 120×90px 预留区判断和标注，不要圈定过大范围。
- 问题清单使用阅读型表格版式。
- 问题清单表头和正文必须使用同一套 4 列网格，不能自由摆放导致错位。
- 问题清单内容来自当前图片，不来自历史案例。
- 硬性规则没有被降级成软性优化。
- 明显图层样式问题按硬性必改处理。
