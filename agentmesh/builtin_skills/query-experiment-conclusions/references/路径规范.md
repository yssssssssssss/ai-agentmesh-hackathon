# 路径规范

**skill 读写文件时的路径基准和查找逻辑。所有 skill 内的其他文档在写路径时都遵守本规范。**

---

## 部门基准路径(BASE)

所有 skill 操作都以**部门根目录**为基准。当前部门是 `plus-and-new-channel`,项目内的路径是:

```
{仓库根}/jd-design-system-md-v16/product-architecture/plus-and-new-channel/
```

**代码里用 `$BASE` 变量代表这个路径。**

---

## 默认相对路径(优先用)

skill 每次执行时,默认相对路径是 `$BASE`。所有资源都在 `$BASE` 下:

| 用途 | 相对 $BASE 的路径 |
|---|---|
| 实验索引 | `$BASE/_knowledge/experiments/INDEX.json` |
| 实验 md | `$BASE/_knowledge/experiments/{分类}/{缩写}.md` |
| 实验图片 | `$BASE/_knowledge/experiments/assets/{缩写}-mock.png` |
| 分类预览页 | `$BASE/_knowledge/experiments/previews/{分类}.html` |
| 总目录页 | `$BASE/_knowledge/experiments/index.html` |
| 空白模板 | `$BASE/_knowledge/experiments/EXPERIMENT-TEMPLATE.md` |
| README | `$BASE/_knowledge/experiments/README.md` |
| 组件权威清单 | `$BASE/_foundation/components/COMPONENT_NODE_MAP.json` |
| 组件规范文件 | `$BASE/_foundation/components/{组件 slug}/spec.md` |
| register skill | `$BASE/_skills/register-experiment/` |
| query skill | `$BASE/_skills/query-experiment-conclusions/` |

## $BASE 的自动定位(双保险)

skill 执行前**先定位 $BASE**,顺序尝试:

### 方式 A · 假设路径(优先)

假设仓库结构没变,直接用**从 skill 自身位置往回推**的固定路径:

```
skill 在:  $BASE/_skills/{skill-name}/SKILL.md
$BASE 是:  从 skill 位置往上两层
```

Bash 定位:
```bash
# 假设 skill 目录结构不变
SKILL_DIR=$(dirname "${BASH_SOURCE[0]:-$0}")   # 当前 SKILL.md 所在目录
BASE=$(cd "$SKILL_DIR/../.." && pwd)            # 往上两层
```

### 方式 B · 兜底往上搜(方式 A 失败时用)

如果方式 A 定位到的目录**不含 `_knowledge/experiments/INDEX.json`**,启动"往上搜"逻辑:

```bash
# 从当前工作目录往上找,直到遇到含 INDEX.json 的目录
BASE=$(pwd)
while [ "$BASE" != "/" ]; do
  if [ -f "$BASE/_knowledge/experiments/INDEX.json" ]; then
    break
  fi
  BASE=$(dirname "$BASE")
done

# 找不到就报错
if [ "$BASE" = "/" ]; then
  echo "❌ 找不到部门根目录(需要含 _knowledge/experiments/INDEX.json)"
  exit 1
fi
```

### skill 执行前的定位模板

skill 执行前**必须先运行**这段定位:

```bash
# ============ 定位 $BASE ============
# 方式 A:从 skill 位置推
SKILL_DIR="{SKILL_MD_DIR}"  # 由 skill 自动填充
BASE_A="$SKILL_DIR/../.."

# 检查方式 A 是否有效
if [ -f "$BASE_A/_knowledge/experiments/INDEX.json" ]; then
  BASE="$BASE_A"
else
  # 方式 B:往上搜
  BASE=$(pwd)
  while [ "$BASE" != "/" ]; do
    [ -f "$BASE/_knowledge/experiments/INDEX.json" ] && break
    BASE=$(dirname "$BASE")
  done
  [ "$BASE" = "/" ] && { echo "❌ 找不到部门根"; exit 1; }
fi

echo "✅ BASE=$BASE"
# ============ 定位结束 ============
```

**注意**:skill 内部实际调用时,Claude 会用 `Bash` 工具执行类似逻辑。上面的模板是给 skill 文档参考,实际写法用普通 shell 命令即可。

## md / HTML 文件内部的相对路径

md 和 html 文件里的链接,基准不是 $BASE,而是**该文件自己的位置**。

### md 里的图片引用

```
实验 md 位置:  $BASE/_knowledge/experiments/{分类}/{缩写}.md
图片位置:      $BASE/_knowledge/experiments/assets/{缩写}-mock.png

md 里写:
![方案示意图](../assets/{缩写}-mock.png)
              ↑ 从"分类/"往上一层,再进 assets/
```

### md 里的组件规范引用

```
实验 md 位置:  $BASE/_knowledge/experiments/{分类}/{缩写}.md
组件规范位置:  $BASE/_foundation/components/{组件 slug}/spec.md

md 里写:
[组件名](../../_foundation/components/{组件 slug}/spec.md)
        ↑ 从"分类/"往上两层,再进 _foundation
```

### HTML 里的链接

```
分类预览 HTML 位置:  $BASE/_knowledge/experiments/previews/{分类}.html
返回总目录:          ../index.html
引用图片:            ../assets/{缩写}-mock.png
引用组件规范:        ../../_foundation/components/{组件 slug}/spec.md
```

### 中文和空格的 URL 编码

**md 里的链接**:VSCode 能识别中文和空格,不用编码
```markdown
[腰部楼层](../../_foundation/components/mid floors/spec.md)  ✅ 空格 OK
[楼层氛围](./楼层氛围.md)                                     ✅ 中文 OK
```

**HTML 里的 href**:**必须** URL 编码
```html
<a href="../../_foundation/components/mid%20floors/spec.md">  ✅ 空格→%20
<a href="../商卡/送礼逛品商卡.md">                              ⚠️ 中文可以不编码,但推荐编码
```

## 迁移到其他仓库时的适配

如果这份 skill 未来复制到其他部门/仓库:

1. **不需要改代码**,只要目标仓库有相同的目录结构就行:
   ```
   {某个位置}/_knowledge/experiments/
   {某个位置}/_foundation/components/
   {某个位置}/_skills/register-experiment/
   {某个位置}/_skills/query-experiment-conclusions/
   ```

2. **方式 B**(往上搜)保证在任何仓库结构下都能定位

3. **如果目标仓库把资源放在不同的相对位置**,只需要改本文件里的"默认相对路径"表,skill 的其他文档不用动

## 常见错误

❌ **错误示例 1**:直接写 `_knowledge/experiments/INDEX.json`
```bash
cat _knowledge/experiments/INDEX.json   # ❌ 不知道从哪儿算起
```

✅ **正确**:
```bash
cat "$BASE/_knowledge/experiments/INDEX.json"
```

❌ **错误示例 2**:写死绝对路径 `/Users/xxx/Documents/...`
```bash
cat /Users/hujinrui.axin/Documents/2C-DesignWiki/...   # ❌ 换机器就崩
```

✅ **正确**:总是从 $BASE 出发。

❌ **错误示例 3**:HTML 里写中文路径不编码
```html
<a href="../父子嵌套/父子Tab高度.html">   ⚠️ 可能在某些浏览器/服务器出问题
```

✅ **正确**:URL 编码
```html
<a href="../%E7%88%B6%E5%AD%90%E5%B5%8C%E5%A5%97/%E7%88%B6%E5%AD%90Tab%E9%AB%98%E5%BA%A6.html">
```

## 推到 coding 后的注意事项

1. **别改仓库结构**:如果部门目录 rename 了(如 `plus-and-new-channel` → 别的名字),skill 的方式 A 会失效,方式 B 会兜底
2. **别把 skill 挪走**:skill 目录 `_skills/{skill-name}/` 保持在部门根下
3. **推送 assets/ 里的图片**:实验图片是 skill 的核心产物,别 gitignore
4. **INDEX.json 是唯一权威**:所有查询都从这里出发,md 文件是二级依据

## 检查清单(skill 每次执行前的自检)

- [ ] `$BASE` 已定位并含 `_knowledge/experiments/INDEX.json`
- [ ] `$BASE/_foundation/components/COMPONENT_NODE_MAP.json` 存在(register 才需要)
- [ ] 目标分类目录 `$BASE/_knowledge/experiments/{分类}/` 存在或允许创建
- [ ] `assets/` 目录存在
- [ ] `previews/` 目录存在

任何一项失败 → 停止执行,提示用户"目录结构异常,请检查部门根"。
