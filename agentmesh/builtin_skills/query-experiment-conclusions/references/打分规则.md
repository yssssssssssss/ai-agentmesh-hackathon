# 打分规则

用户提问 → skill 抽取关键词 → 对每个实验计算总分 → 按分层展示。

## 打分维度

对每个实验按以下维度打分,累加:

| 维度 | 权重 | 命中判断 |
|---|---|---|
| **主组件命中** | ⭐ **+40** | 提问关键词与实验 `组件.主` 的 slug/中文名匹配(或同义词) |
| **分类命中** | +25 | 提问关键词与实验 `分类` 匹配(商卡/腰部楼层/父子嵌套) |
| **副组件命中** | +20 | 提问关键词与实验 `组件.副` 数组中的任一元素匹配 |
| **复用条件关键词** | +15 / 条 | 提问关键词与 md 里"复用条件"的 `维度: 取值` 部分匹配(取值命中即算) |
| **人群拆分维度** | +15 | 提问关键词与实验 `人群拆分.拆分维度` 或 `人群拆分.人群列表` 匹配 |
| **一句话结论关键词** | +10 / 词 | 提问关键词命中 `一句话结论` 里的实义词(动词/名词) |
| **业务线命中** | +5 | 提问明确提到"PLUS / 新品 / 排行榜"且匹配 |
| **意图反问命中** | +30(仅失败/负向实验) | 提问含"失败/坑/避坑/负向"时,负向或废弃实验+30 |

## 落地建议加权系数

累加分 × 落地建议系数(体现"这个方案实际能不能抄"):

| 落地建议 | 系数 |
|---|---|
| 🚀 全量上线 | **×1.2** |
| 🔄 迭代优化 | ×1.0 |
| 🎯 分人群上线 | ×0.8 |
| 🚫 废弃方案 | ×0.3(降权,但不排除,可当反面教材) |

## 是否可沉淀加权

| 可沉淀 | 系数 |
|---|---|
| 🌟 是 | ×1.1 |
| 🔒 否 | ×0.9 |

**最终得分公式**:
```
final = 累加分 × 落地建议系数 × 可沉淀系数
```

## 阈值 · 分层展示

| 得分 | 分层 | 展示方式 |
|---|---|---|
| ≥ 60 | 强相关 | top 3 完整卡片(读 md 补齐字段) |
| 30-59 | 弱相关 | 折叠区,只显示标题 + 一句话结论(不读 md) |
| < 30 | 忽略 | 不展示 |

## 排序规则

**主排序**:得分降序

**次排序**(同分时):
1. 时间倒序(新的优先)
2. 可沉淀=是 优先
3. 落地建议为全量上线的优先

## 具体例子

### 例 1 · 用户问"高单价商品适合什么样的商卡?"

关键词抽取(展开同义词):
- 组件:商卡 → new-product-card
- 场景:高单价 → 客单价偏高、高价格

打 EXP-1(送礼逛品商卡):
```
+ 40  主组件 new-product-card 命中
+ 25  分类"商卡"命中
+ 15  复用条件"客单价偏高"命中(通过同义词"高单价")
+ 10  一句话结论含"客单价偏高"和"点击转化"
+  5  业务线新品(用户没提业务线,不加分,或+5 保底)
------
= 95 × 1.2(全量上线)× 1.1(可沉淀)
= 125.4 → 强相关
```

打 EXP-2(楼层氛围):
```
+  0  主组件不匹配
+  0  分类不匹配
+  0  复用条件不匹配
------
= 0 → 忽略
```

**输出**:top 1 强相关 = EXP-1,完整卡片。

### 例 2 · 用户问"楼层视觉氛围重不重要?"

关键词抽取:
- 组件:楼层 → mid floors、腰部楼层
- 场景:视觉氛围 → 去色、简化

打 EXP-2(楼层氛围):
```
+ 40  主组件 mid floors 命中
+ 25  分类"腰部楼层"命中
+ 15  复用条件"去色/简化"命中(通过同义词"视觉氛围")
+ 10  一句话结论含"氛围"和"利益点"
------
= 90 × 1.2(全量上线)× 1.1(可沉淀)
= 118.8 → 强相关
```

**输出**:top 1 强相关 = EXP-2,完整卡片。

### 例 3 · 用户问"父子 Tab 有踩过坑吗?"(反问型)

关键词抽取:
- 组件:Tab → secondary-tabs_、父子嵌套
- 意图:踩坑 → 失败 / 负向 / 废弃

假设未来录了 3 个父子嵌套实验:
- EXP-A 父子Tab高度(正向 / 全量上线)
- EXP-B 父子Tab颜色差异(负向 / 废弃方案)
- EXP-C 父子Tab间距(正向 / 迭代优化)

打分:
```
EXP-A: 40 + 25 = 65 × 1.2 × 1.1 = 85.8
EXP-B: 40 + 25 + 30(意图反问=负向命中!)= 95 × 0.3 × 0.9 = 25.65 → 忽略?
EXP-C: 40 + 25 = 65 × 1.0 = 65
```

⚠️ 这里有问题:EXP-B 明明是用户想找的"失败案例",但 0.3 系数把它打到 < 30 分被忽略了。

**修正规则**:当"意图反问"命中时,**跳过落地建议加权系数**,直接用累加分。

```
EXP-B(修正): 40 + 25 + 30 = 95 → 强相关 → 展示为"❗ 历史失败 · 参考避坑"
```

## 关键词命中判断

**基础匹配**:
- 完全字面匹配 → 命中
- 大小写不敏感

**同义词展开**(见 `同义词表.md`):
- 用户"高单价" ↔ 实验里"客单价偏高" → 命中
- 用户"Tab" ↔ 实验里"标签栏"/"父子嵌套" → 命中

**部分匹配**:
- 用户"客单价高" 匹配 实验"客单价偏高" → 命中(部分匹配算 0.7 权重)
- 用户"氛围" 匹配 实验"去氛围" → 命中(部分匹配)

**多词短语**:
- 用户输入"高单价商品" 拆成 ["高单价", "商品"] 分别匹配
- 全部命中 = 加满分
- 部分命中 = 按命中比例加分

## 边界情况

**情况 1 · 用户提问太宽泛**(如"怎么提升点击率?")
- 所有实验都可能匹配一点,但都不强
- 处理:引导补问 1 轮,让用户具体化组件/场景

**情况 2 · 用户提问太具体**(如"25 岁女性用户对京东红色 vs 蓝色的偏好")
- 大概率无实验完全匹配
- 处理:诚实说"没强相关" + 列弱相关(相同组件或相似人群)

**情况 3 · 用户拼错关键词**
- 如"腰部楼层" 拼成"腰间楼层"
- 处理:同义词表兜底,不行就让用户重新描述

**情况 4 · 用户用英文提问**(如"how about product card?")
- 匹配组件英文 slug(new-product-card)+ 常见中英翻译
- 拿不准让用户中文重问

## 更新规则

**每次新加实验时**,skill 不需要改代码,自动从 INDEX.json 读取新实验参与打分。

**加了新分类时**(如"标签栏"),skill 自动识别,不需要改配置。

**加了新的意图关键词或同义词时**,更新 `同义词表.md` 即可。
