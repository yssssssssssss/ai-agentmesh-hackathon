# query-experiment-conclusions · 实验反查 Skill

用于**读取** PLUS 与新品频道设计部已录入的 AB 实验结论,回答"历史有没有做过类似的""这个方向能不能抄""有没有踩过坑"这类问题。

## 一句话说清

**"给我一个方案设想 / 组件 / 场景 / 人群 → 告诉我历史上做过什么类似的、结果怎样、能不能抄、要不要避坑。"**

## 路径基准 · 必读

**skill 内所有路径都以 `$BASE` 为基准**,`$BASE` 是部门根目录:
```
$BASE = {仓库根}/jd-design-system-md-v16/product-architecture/plus-and-new-channel
```

**执行前必须先定位 $BASE**,详见 `references/路径规范.md`。核心逻辑:
1. 假设 skill 目录不变,`$BASE = $SKILL_DIR/../..`(优先)
2. 如果方式 1 失败,从当前 pwd 往上搜到含 `$BASE/_knowledge/experiments/INDEX.json` 的目录

**关键路径**:
| 用途 | 路径 |
|---|---|
| 实验索引(必读) | `$BASE/_knowledge/experiments/INDEX.json` |
| 实验 md(强相关时读) | `$BASE/_knowledge/experiments/{分类}/{缩写}.md` |
| 分类预览页(输出链接) | `$BASE/_knowledge/experiments/previews/{分类}.html` |

## 任务边界

**只做**:
- ✅ 读取 `$BASE/_knowledge/experiments/INDEX.json` 和 `.md` 文件
- ✅ 按用户输入匹配、打分、排序、返回相关实验
- ✅ 附带数据、复用条件、命中原因、HTML/md 链接

**不做**:
- ❌ 生成新方案 / 推理"如果 XX 会怎样"(容易编造)
- ❌ 修改任何文件(纯读取,不落盘)
- ❌ 跨部门查询(只查本部门 `plus-and-new-channel/_knowledge/experiments/`)
- ❌ 匹配度低时强行凑答案(诚实说"没找到强相关")

## 必读引用

执行反查前,按需读取:

- `references/路径规范.md` — **首先读**,含 $BASE 定位逻辑和所有路径清单
- `references/打分规则.md` — 每个字段的权重、加权系数、阈值
- `references/同义词表.md` — 关键词扩展映射(如 "高单价" ↔ "客单价偏高")
- `references/输出格式.md` — 输出模板,含 HTML 链接、命中原因、失败实验警告

## 反查流程

### 第 1 步 · 判断查询意图

用户可能的问法(5 类):

| 类型 | 例句 |
|---|---|
| 组件问 | "商卡有没有做过类似的?" |
| 场景问 | "高单价商品适合什么样式?" |
| 人群问 | "对高消费用户什么改动更有效?" |
| 反问型 | "楼层氛围失败过吗?" |
| 精准问 | "和 XX 实验类似的还有哪些?" |

不属于以上、也没触发词的,不要主动调用 skill。

### 第 2 步 · 抽取关键词

从用户提问抽取 4 类关键词:

1. **组件关键词** — 商卡 / new-product-card / 楼层 / mid floors / Tab / secondary-tabs_ / feeds / home-banner / home-column / 百宝箱 ...
2. **场景关键词** — 客单价 / 价格 / 逛品 / 送礼 / 权益 / 入口 / 楼层视觉 / 密度 ...
3. **人群关键词** — 高消费 / 低消费 / 新用户 / 老用户 / PLUS 用户 / 沉默用户 / 高单价 ...
4. **意图关键词** — 提升 / 优化 / 简化 / 去掉 / 加 / 失败 / 坑 / 避坑 ...

用 `references/同义词表.md` **扩展关键词**。例:
- 用户说"高单价" → 同时匹配"客单价偏高"、"高价格"、"客单价高"
- 用户说"Tab" → 同时匹配"标签栏"、"父子嵌套"、"二级 tab"

### 第 3 步 · 读 INDEX.json 打分

按 `references/打分规则.md`:

1. 读 `$BASE/_knowledge/experiments/INDEX.json`
2. 对每个实验按维度打分(组件命中 / 分类命中 / 复用条件 / 人群 / 一句话结论 / 业务线)
3. 用落地建议加权系数(全量 ×1.2 / 迭代 ×1.0 / 分人群 ×0.8 / 废弃 ×0.3)
4. 分数分层:
   - **≥ 60 分** = 强相关 → top 3 完整展示
   - **30-59 分** = 弱相关 → 折叠区,只显示标题 + 一句话
   - **< 30 分** = 不展示

### 第 4 步 · 补充信息(读 md)

对**强相关**的 top 3,从 `INDEX.json` 拿不到的字段(如完整数据、复用条件、慎用条件),Read 对应的 md 文件补齐。

弱相关的**不读 md**,只用 INDEX.json 的字段(省 token)。

### 第 5 步 · 引导式补问(可选)

如果所有实验打分都 < 60(没有强相关):

**先不要直接说"没匹配"**,而是**引导补问 1-2 个问题**:

```
你说"商卡怎么办",我这边有几个匹配可能,想再确认一下:

  1) 你想解决什么问题?
     [a] 提升点击 / 转化
     [b] 简化商卡信息
     [c] 差异化人群展示
     [d] 其他:___

  2) (可选)针对特定人群吗?(如高消费/新用户)

回答后我再筛选。
```

补问最多**一轮**,还查不到 → 老实说"没找到强相关"+ 列弱相关。

### 第 6 步 · 输出

按 `references/输出格式.md` 的**极简模板**:

- **直接给结论**(一句话答用户的问题)
- **关键数据**(核心指标即可,不必 P0/P1/P2 全列)
- **强相关实验**只给标题 + HTML 预览链接 + md 链接
- **建议** 1-3 条,基于实验数据
- 弱相关**只列标题 + 链接**,不展开数据/结论
- 失败实验(负向 / 废弃)**红色警告 + 标签"❗ 历史失败 · 参考避坑"**

## 硬性要求

- ✅ **先给一句话直接结论**,不要绕
- ✅ 每条强相关推荐**必须给 HTML 预览链接**(优先)+ md 链接(备选)
- ✅ 数据必须**直接引用 md**,不重新计算、不加工
- ✅ 失败实验(负向 / 废弃方案)**必须加醒目警告**,防止误抄
- ✅ 没匹配时**先引导补问一轮**,不要立刻说"没找到"
- ❌ **不写"命中原因"独立小节**(用户点开链接一眼就懂,打分逻辑是内部逻辑)
- ❌ **不为强相关写长卡片**(数据/结论/慎用/命中原因逐条列出会太重)
- ❌ **弱相关不写数据、不写一句话结论**,只留标题 + 链接

## 禁止

- ❌ 猜测数据(拿不到就说"暂无数据")
- ❌ 组合多个实验的数据得出新结论(会编造)
- ❌ 生成用户没提供依据的建议
- ❌ 修改 experiments 目录里的任何文件
- ❌ 对弱相关实验也读 md(浪费 token)
- ❌ 单次输出超过 **400 字**(强相关 1 个)/ **600 字**(强相关 2-3 个),超了要削建议和弱相关
- ❌ 写"命中原因"、"慎用条件"独立小节(合并到"建议",或省略)
- ❌ 强相关写超过 3 行元信息(结论 emoji + 落地建议 emoji + 标题 + 一条数据即可)

## 完成标准

- 用户**一眼**能看到直接结论
- 用户能通过 HTML 预览链接看到完整实验(不需要读长卡片)
- 遇到失败实验时,用户不会误以为要抄
- 建议**具体可操作**,不是虚话
- 单次输出 ≤ 400-600 字

## 例子

### 例 1 · 组件问

```
用户: "商卡有没有做过一行一 vs 一行二的实验?"

skill 抽取:
  组件: new-product-card(商卡)
  关键词: 一行一、一行二

打分:
  送礼逛品商卡(EXP-1) = 40(主组件) + 15(复用条件"客单价偏高"部分匹配)
                        + 20("一行一 vs 一行二"关键词双命中)
                        = 75 → 强相关
  楼层氛围(EXP-2) = 0 → 不展示

输出: top 1 强相关 · 完整卡片
```

### 例 2 · 反问型(避坑)

```
用户: "楼层氛围失败过吗?"

skill 抽取:
  组件: mid floors(楼层)
  意图: 失败 / 避坑

打分:
  楼层氛围(EXP-2) = 40(主组件) + 25(分类"腰部楼层")
                    + 15(复用条件"去色/简化"匹配"氛围")
                    = 80 → 强相关
  但方向是"正向 + 全量上线",不是失败案例

输出:
  "❌ 没找到失败案例。但有 1 个相关实验(不是失败,是正向的):
   [楼层氛围 vs 无氛围]
   💡 结论:去氛围反而更好,不是失败,是发现氛围没价值
   ..."
```

### 例 3 · 引导式补问

```
用户: "怎么做能提升点击率?"

skill: 太宽泛,先补问

  你想优化的场景是哪种?
    [a] 频道首屏(首焦/banner)
    [b] 商品卡(商卡)
    [c] 楼层入口
    [d] Tab 切换
    [e] 其他:___

用户: b

skill: 现在按"商卡 + 提升点击"重新匹配 → 输出结果
```
