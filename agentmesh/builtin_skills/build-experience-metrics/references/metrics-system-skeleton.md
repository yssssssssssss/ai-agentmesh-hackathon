> 本文件是 **build-experience-metrics skill 自己的产出结构**，不是 wiki 正典。
> HEART 五维定义、GSM 三步、基准值（SUS=68/SEQ≈5.5…）、量表题干与计分、纵向追踪协议、B 端北极星四候选与频控规则、数据标准化公式等正典内容**一律运行时从 `research-wiki/methods/.../`、`research-wiki/assets/scales/...` 现读**（见 SKILL.md 第 2 步），不在此复制。
> 下面方括号 `[…]` 是占位槽，按本次 brief 与读到的正典填实。各表的列/口径**以运行时读到的正典为准**，下方列名只是形态示意。
> **只输出本次实际用得上的块**；用户只要单期快照、不追踪时，纵向追踪方案块可省并在运行说明声明。

## 〇、brief 研判小结（放在最前，统领全篇）

```
## brief 研判

- 产品/系统：[名称]，形态：[C 端 / B 端（采销/供应商/中后台…）]
- 产品阶段：[冷启动·探索期 / 深耕·打磨期 / 突破期]，对体系详略的影响：[一句话]
- 业务目标：核心 = [要提升什么]；护栏 = [不可恶化的底线]
- 可用数据源：[有无行为埋点 / 能否投问卷 / 有无历史基线·竞品基准 / 有无后台标签可下钻]
- 是否跨版本·跨平台·跨人群比较：[是 → 配纵向追踪/标准化；否 → 说明]
- 采集可行性声明：[当前能落地的指标（如主观问卷类）vs 暂落不了地、需先补埋点/基线的指标]
```

> 采集可行性声明是本 skill 的"诚实底牌"：让使用者一眼看清哪些指标现在就能采、哪些要先补埋点或基线才落得了地（呼应 HEART 从 0 到 1「一期多以主观数据为主」）。

## 一、体验度量体系

### 1.1 GSM 推导链（体系的脊梁，先目标后指标）

逐目标一行，显式写出 G→S→M，别跳过目标直接堆指标。

```
## GSM 推导（目标 → 信号 → 指标）

| 目标(G) | 信号(S：可观测、对体验敏感、不易被刷) | 指标(M：口径清晰) | 对应 HEART 维度 | 提升(核心)/守住(护栏) |
|---|---|---|---|---|
| [本次核心目标] | [什么现象说明在向目标靠近] | [落成什么数] | [H/E/A/R/T] | 核心 |
| [护栏目标] | [什么现象说明底线被破] | [守住什么数] | [H/E/A/R/T] | 护栏 |
| … | … | … | … | … |
```

### 1.2 HEART 维度选取（3–4 维，不硬凑五维）

```
## HEART 维度选取（按目标选 3–4 维；标 C/B 端选型理由）

- ✅ 选入：[如 Happiness — 因为本次核心目标是…]、[Task success — B 端任务导向，重点看任务成功/效率]…
- ⬜ 未选：[如 Engagement — B 端用户"不得不用"，参与度不反映体验质量，故不选]…
- 选型说明：[C 端 / B 端] → [为何这样取舍]
```

### 1.3 北极星指标 + 护栏指标

```
## 北极星指标（一个全局体验指标，定方向）

- 北极星：[指标名]（[B 端四候选：满意度/费力度/继续合作意愿/推荐意愿 之一；或 C 端 满意度/NPS]）
- 为什么是它：[结合本产品/目标的理由 + 该指标的优劣（取自正典）]

## 护栏指标（不可恶化的底线，跌破即预警）

- [护栏指标1]：守住 [基线/不低于上版]，原因：[猛拉北极星可能暗伤它，如 采纳↔愉悦度/留存]
- [护栏指标2]：…
```

### 1.4 采集口径看板

逐指标一行。愉悦度/任务成功/忠诚维度**直接取标准量表口径并标基准**；客观指标无固定满分的，给标准化赋分方案。

```
## 采集口径看板

| HEART 维度 | 指标(M) | 口径（分子/分母·统计周期·样本来源） | 量表/计分 | 基准/目标值 | 核心/护栏 |
|---|---|---|---|---|---|
| Happiness | [SUS / CSAT] | [问卷采集·每迭代1波·目标用户抽样] | [SUS 10题5点→0–100] | [SUS≥68，目标75，转百分位读] | 核心 |
| Task success | [任务完成率/SEQ] | [可用性测试·任务级·起点→终点判定] | [完成率%；SEQ 单题7点] | [完成率≥90%，SEQ≥5.5] | 核心 |
| Engagement | [周人均会话时长] | [行为日志·周·全量] | [均值] | [不低于上版] | 护栏 |
| [客观·性能] | [冷启动耗时] | [埋点·周·全量] | [标准化赋分：基准值测定/区间映射] | [门槛60/目标80/挑战100] | 护栏 |
| … | … | … | … | … | … |
```

> 量表口径（题数/点数/计分/基准）一律取自 `assets/scales/standardized-ux-scales.md`，别自造；分数对标百分位、不看绝对值。客观指标折分思路取自 `data-standardization.md`，标"标准化值仅供比较"。

### 1.5 拆解度量体系（拆解树，定位问题的地基）

二选一（或组合），把北极星拆到可定位颗粒度。

```
## 拆解树（方法：[因子分解法 / 客户旅程法]）

[因子分解法示例]
北极星：[XX 产品满意度]
├─ [子系统A] 满意度 = [模块a1] + [模块a2] + …
├─ [子系统B] 满意度 = [模块b1] + …
└─ …

[客户旅程法示例]
北极星：[黄金流程满意度]
[触点1 首页] → [触点2 搜索] → [触点3 商详] → … → [触点N]
  其中 [首页] 体验关键要素：[整体布局 / 入口查找 / 视觉风格 / …]
```

### 1.6 采集方案

```
## 采集方案

- 采集方式：[问卷调研（全面·回收率低）/ 场景化弹窗（即时·维度单一）/ 可用性测试（系统·成本高）]，本次选 [..] 因为 [..]
- 最小题型单元：体验评分（[推荐 0–10 级 / 长问卷可用 5–6 级]）+ 不满意原因（[二级归因多选]）+ 开放题采集原声
- 净值口径：[NSS = 满意% − 不满意%；0–10 级下 =(9–10)% − (0–6)%]
- 频控（B 端必配三层）：单题 [1–3 次/周期]、全局 [每人每天≤1 份]、填答 [累计≤3 次]
- 最小样本量：[95% 置信、3% 误差；总体比例未知设 50% → 约 n=…]；样本须覆盖关键差异维度 [..]
- 后台标签（供下钻）：[身份角色 / 高低频 / 产品模块 / 版本 …]
- 标准化前处理（如需）：[跨平台/跨量纲/客观指标赋分 → Z-score/双重标准化/正态变换赋分]
```

## 二、纵向追踪方案（持续怎么量、跟谁比）

```
## 纵向追踪方案（口径冻结 + 基线 + 适应期再测）

| 项目 | 本次设定 | 跨版本要求 |
|---|---|---|
| 固定关键任务集 | [任务1…任务N（约 5–10 个高优）] | 表述、步骤完全照搬，冻结 |
| 行为指标 | [任务成功率 / 耗时 / 可寻性…] | 口径冻结、分子分母固定 |
| 态度指标 | [SEQ / SUS / NPS…] | 题项、计分不变 |
| 参照基线 | [自身早期版本 / 竞品 / 行业 / 既定目标] | 首次无历史→先测竞品/行业/目标立基线 |
| 采集时点 | 改版后留 [2–3 周(高频)/4–5 周(低频)] 再测 | 避开 D1 新鲜感峰值与变化厌恶期 |
| 指标分层 | 领先[..] / 同步[..] / 滞后[..] | 区分早期信号与长期价值 |
| 外部干扰 | [营销/季节/大促/经济…] | 每波次登记、入附录 |
| 追踪频率 | [每迭代 / 每月 / 每季] | 固定频率重跑 |
| （可选）ROI | [UX 指标↔客服成本/营收/线索] | 向上证明改版价值 |
```

> 用户只要单期快照、不追踪时本块可省，但在运行说明声明"未配纵向追踪（仅单期快照），无基线时单期分数难解读"。

## 五、形态示意（仅示范「长什么样」，**勿照抄内容**——务必按真实 brief 重写）

> 下例是凭空编的格式演示，不是任何正典内容、不是真实数据，也不针对真实产品。看完格式即弃。

```
## brief 研判
- 产品：某采销比价系统，形态：B 端（采销）；阶段：深耕·打磨期
- 业务目标：核心 = 提升比价查询的任务效率与满意度；护栏 = 系统性能（卡顿率）不恶化
- 可用数据源：有性能埋点；可在系统内投场景化问卷；无历史基线
- 跨版本比较：是 → 配纵向追踪；暂不跨平台，无需标准化
- 采集可行性：满意度/费力度（场景化问卷）现在就能采；任务成功率需补任务级埋点

## GSM 推导
| 目标(G) | 信号(S) | 指标(M) | 维度 | 核心/护栏 |
|---|---|---|---|---|
| 比价更省力 | 用户更快完成比价、抱怨更少 | 比价任务费力度 CES | Task success | 核心 |
| 别为提速牺牲稳定 | 卡顿不增多 | 卡顿率 | （护栏·性能） | 护栏 |

## 北极星指标
- 北极星：采销系统满意度（B 端四候选中选"满意度"，因需在多模块灵活即时收集反馈）
- 护栏：卡顿率（守住 ≤ 上版），原因：提速改造常以稳定性为代价

## 采集口径看板（节选）
| 维度 | 指标 | 口径 | 量表/计分 | 基准/目标 | 核心/护栏 |
|---|---|---|---|---|---|
| Happiness | 模块满意度 | 场景化弹窗·每周·按权限过滤非目标用户 | 0–10 级，NSS=(9–10)%−(0–6)% | 不低于基线 | 核心 |
| Task success | 比价费力度 | 任务结束即问·场景化 | CES | 越低越好 | 核心 |

## 指标质量自检（节选）
| 检查项 | 结论 | 证据/怎么改 |
|---|---|---|
| C/B 端选型对（B 端别照搬活跃类） | ✅ | 未用活跃/时长类做核心，用满意度/费力度 |
| 采集不打扰（频控三层） | ⚠️ | 已配单题+全局频控，填答频控待补 |
⚠️ 维度/口径基于 status: draft 的 experience-metrics-heart.md；任务成功率依赖埋点，当前未落地。
```

> 注意上例如何：GSM 先写目标再落指标、北极星只有一个且说明了选型理由、护栏配在"会被暗伤"的维度上、量表用了标准口径并标基准、就地标注了 draft 与"埋点未落地"——**形式照此，内容必须按真实 brief 重新生成**。
