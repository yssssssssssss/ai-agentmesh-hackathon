# 示例 Case · 看赚高TGI用户 1元红包角标透出

> 本示例展示 prd-feasibility skill 处理一个真实 PRD 的完整过程,可作为新 case 的参考。

## 输入

- **PRD URL**: `https://joyspace.jd.com/pages/v5mwXxvbqybQMDumlZnN`
- **关键页面截图**: 7 张手机截图拼成的总图 `shiyantu.png`(首页/红包弹窗/看赚面板/提现页/提现弹窗/到账成功/小手引导)

## 分析过程

### 1. 抓 PRD

```bash
o2 launch webcli joyspace export v5mwXxvbqybQMDumlZnN -f json
# 输出 markdown 到 ~/Downloads/joyspace-export/
```

### 2. 裁切截图

```python
# 用 templates/crop_screenshots.py
POSITIONS = [
    ("01_homepage",  330,  120, 1185, 2100),  # 7 张截图横排
    ...
]
```

### 3. 走 6 步分析

**Step 1 · 业务逻辑硬伤(3 个)**

| # | 硬伤 | 为什么 | 影响 |
|---|---|---|---|
| 1 | 收益预估有「选择偏差」 | "1元角标 CTR=3.71%" 数据来自已激活用户,推算到沉默用户不成立 | +42w → +13w~21w |
| 2 | 公式漏斗缺失 | 点击角标 ≠ 主动 DAU,中间漏两层 | × 49% |
| 3 | "曝光即发奖"白发率高 | 70% 曝光后跳出 = 70% 1元白花 | 成本翻倍 |

**Step 2 · 7 步路径评审**

每步配真实截图 + 颜色评价:
- 1 首页角标 ✅ 合理
- 2 频道弹窗 🟡 需改(曝光发奖改点击发奖)
- 3 关闭后 Toast 🔴 建议删
- 4 跳转提现页 🟠 探讨(见 Section 5)
- 5 提现确认弹窗 🔴 建议删(1元无需二确)
- 6 到账成功页 ✅ 保留
- 7 小手强制引导 🔴 建议改

**Step 3 · 双方案**

- **A 保守**:首页角标 → 弹窗(点击发奖) → 到账成功 → 轻引导,4 步,1 周
- **B 积极**:在 A 基础上,到账后加"再看 30s 视频得 0.5 元"钩子,利用多巴胺高峰

**Step 4 · 数据预估**

涨 4 项:
- 逛 Tab CTR +1.2%~2.0%
- 主动 DAU +6w~12w(vs PRD 的 +42w)
- 沉默用户次留 +8%~15%
- 看赚面板 UV +15%~30%

跌 3 项:
- 防打扰用户 +0.5%~2%
- 角标 7 天衰减 -30%~-50%
- 真实 ROI 1.5~2.5(原 3.77)

监控 3 项:session 时长 / 7-30 日留存曲线 / 任务完成率

**Step 5 · 专题探讨 · 提现页跳转 vs 直接到账**

核心论点:历史"提现页留存 90%"是主动进入的用户,不能预测被动跳入。建议直接到账 + 轻引导。

**Step 6 · 整体结论**

修 4 件事:
1. 修正收益预期(承认偏差,真实 +6w~12w)
2. 路径砍到 4 步(删 Toast / 删二确 / 不强制跳转)
3. 发奖时机改"点击才发"
4. 提现页改直接到账

## 关键经验

1. **截图必须先要** —— 没有真实 UI 截图,流程图可信度差 3 倍
2. **每个硬伤都要带 reasoning 框** —— 解释本质 + 类比 + 影响,而不是简单"这不对"
3. **总是给两套方案** —— 不要只给一套,A/B 对比让产品方有选择空间
4. **数据预估必须分涨/跌/监控** —— 只说涨不说跌不可信
5. **结论标题以"需求成败"为中心** —— 不要写"你可以带去评审",写"让这个需求真正跑通的关键"
