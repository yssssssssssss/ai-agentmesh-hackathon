# 问卷 · 输出骨架与模板

> 本文件是 **generate-survey skill 自己的产出结构**，不是 wiki 正典。
> 问卷设计规范、量表题干与计分口径、检查清单等正典内容**一律运行时从 `research-wiki/` 现读**（见 SKILL.md 第 2 / 4 步），不在此复制。
> 下面的方括号 `[…]` 是占位槽，按本次 brief 与读到的正典填实。

## 一、问卷正文骨架

固定四段式：**封面信 → 指导语 → 分节题目（每维度一节） → 结尾致谢**。

### 封面信（问卷开头）

```
【封面信】
- 我是谁：[主办方 / 调查者身份]
- 调查什么：[主要内容，一句话]
- 为什么做：[研究目的]
- 为什么找你：[抽样标准与方法，简明]
- 对你有什么用 / 大概多久：[填答价值 + 预计时长]
- 不会损害你的利益：[保密 / 匿名 / 数据仅用于研究]
- 奖励细则（商业问卷）：[有则写清，无则删]
```
> 各项的取舍与写法依据运行时读到的规范「问卷构成 / 封面信」要求；能一句话说清就别展开。

### 指导语（投放前的填答说明）

```
【指导语】
- 整体填答说明：[如何作答、保存/提交]
- 特殊概念解释：[把"同城寄送""会员权益"等可能不懂的词说清]
- 复杂题型举例：[多选题注明最多选几项；矩阵题/排序题怎么答]
```

### 分节题目（每个研究维度一节，按 brief 维度数增减）

```
■ 第 N 节：[节标题 = 一个研究维度]
  测量目的：[这一节要回答研究目标里的哪个问题]   ← 给执行者看，投放时不展示

  Q[n].1 [题干]
    题型：[单选 / 多选(最多选 X 项) / 量表 / 矩阵 / 数字评分 / 开放文本 / 排序…]
    量表/选项：[标准量表名+点数+锚点，或现写选项；选项需穷尽·互斥·同层次]
    必填/选填：[ ]
    跳转逻辑：[如「选 0–6 分 → 展示 Q[n].2 归因多选」；「不符甄别 → 终止」；默认无则写"无"]
    ⚠️ 标注：[若现写量表/基于 draft/通用兜底，在此标一句；否则删]
```

节内排序约定：先客观/行为题、后态度/量表题；敏感题（如收入）尽量后置。

### 结尾致谢

```
【结尾】
- 兜底开放题（选填）：[还有什么想补充的 / 最希望改进的一点]
- 致谢 + 后续说明：[感谢 + 奖励发放 / 是否回访]
```

## 二、合规自检结果模板（对照规范检查清单逐条）

> **逐条对照运行时读到的 `methods/standards/questionnaire-design.md`「检查清单」一节**，一项一行。
> 清单条目数与措辞**以现读为准**，不要照搬本模板里的示意行、也不要凭记忆默写条数。

```
## 合规自检结果（对照《问卷设计规范》检查清单，规范 status: [draft/reviewed]）

| # | 检查项（取自规范清单） | 结论 | 证据 / 定位 / 怎么改 |
|---|---|---|---|
| 1 | [清单第 1 项原文要点] | ✅/⚠️/❌ | [对应到本问卷哪处；不通过给修正] |
| 2 | [清单第 2 项…] | ✅/⚠️/❌ | […] |
| … | …（按现读清单逐项补全） | | |

自检结论：[共 N 项，✅ x / ⚠️ y / ❌ z。❌ 已回改至 0 项；保留的 ⚠️ 说明：…]
```

> 规则：有 ❌ 必须回第 3 步改题再自检；保留的 ⚠️ 要逐条说明为何可接受。规范为 draft 时在此声明「基于未评审规范，定稿后需复核」。

## 三、《本次运行说明》模板（固定附在最后，五部分齐全）

> 让使用者知道这份问卷建立在什么之上、哪里可能不牢。逐项填实，没有的写「无」。

```
---
## 本次运行说明

**① 调用的正典**（路径 + status）
- methods/standards/questionnaire-design.md（status: [draft/reviewed/…]）
- assets/scales/standardized-ux-scales.md（status: […]）   ← 用到量表时
- methods/toolbox/collection/[satisfaction-survey/qualitative-questionnaire/scale-development].md（status: […]）
- [models/… 或 scenarios/… 若读了，列全]

**② 应调用但未找到的内容**（缺的正典 / 空目录）
- [如：assets/question-bank/ 不存在或为空 → 本次题目为按规范现写]
- [如：要测的"[维度]"量表库未覆盖 → 按规范现写量表/题]
- [如：未找到贴合「[业务线]」的场景打法 → 通用方法兜底]
- 无则写「无」

**③ 走空的链接**（related 指向但不存在的文件）
- [如：某正典 related 指向 methods/.../xxx.md，该文件未找到]
- 无则写「无」

**④ 基于 draft（未评审）内容的部分**
- [列出哪些题/量表/规则来自 status: draft 的正典；当前依赖多为 draft，自检结论亦基于未评审规范]

**⑤ 反馈入口**
- 问卷有问题或正典需补充，请在此反馈：http://xingyun.jd.com/codingRoot/JD_Research_Wiki/Research_Wiki/settings/issues
---
```

## 四、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实 brief 重写）

> 下例是凭空编的格式演示，不是任何正典内容、不是标准量表题干，也不针对真实项目。看完格式即弃。

```
■ 第 2 节：下单结算流程的费力度与满意度
  测量目的：定位结算流程中最费力、最不满意的环节，转为可执行优化点

  Q2.1 这次下单，从进入结算到完成支付，整体顺不顺？
    题型：数字评分量表（0–10，0=非常不满意，10=非常满意）
    量表/选项：用 NSS 口径（标准量表，取自量表库）
    必填：是
    跳转逻辑：选 0–6 分 → 展示 Q2.2；选 7–10 分 → 跳过 Q2.2
  Q2.2 是哪些地方让你觉得不满意 / 需要改进？（最多选 3 项）
    题型：多选（必填）
    量表/选项：[地址填写繁琐 / 优惠券不好用 / 支付方式少 / 加载慢 / 其他___]（穷尽·互斥·同层次）
    必填：是（仅低分用户可见）
    跳转逻辑：承接 Q2.1 低分分支
  ⚠️ 本节计分口径基于 draft 规范与 draft 量表库（satisfaction-survey / standardized-ux-scales 当前为 draft）。
```
> 注意上例如何让题型与目标匹配（测"哪些问题"用多选）、如何写量化锚点（0–10 而非"经常/有时"）、如何写跳转、如何就地标 draft——**形式照此，内容必须按真实研究目标、人群、维度重新生成**。
