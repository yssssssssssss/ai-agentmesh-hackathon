# 研究方案 · 输出骨架与模板（阶段二产出）

> 本文件是 **generate-research-plan skill 自己的产出结构**，不是 wiki 正典。
> 方案各段的具体规则（方法怎么做、流程怎么走、抽样怎么定）**一律运行时从 `research-wiki/` 现读**（见 SKILL.md 第 2.1–2.6 步），不在此复制。
> 骨架对齐 `methods/standards/research-project-workflow.md` 的「方案撰写」结构——运行时以读到的为准；下面只给填写槽位与写法提醒。

---

## 一、研究方案骨架

```
# 研究方案：[题目]

## 一、研究目的
[这次研究属探索 / 描述 / 解释中的哪类？要解决 brief 里的什么核心问题、支持什么决策。
 简明说清"做这件事对决策的价值"。]

## 二、研究内容
[把研究目的拆成几块要回答的内容（纵向逐层分解 + 横向按角色/工作拆，呼应坑四）。
 这几块后面会一一对应到方法与交付。]

## 三、研究方法（选型 + 理由）
[选用的采集 + 分析方法组合，逐个说明：
   - 方法 X（来自 methods/toolbox/.../X.md，status: […]）：为什么用它——它能回答研究内容里的哪一块。
   - 分析 Y（来自 methods/toolbox/analysis/Y.md，status: […]）：产出什么洞察。
 排除项：点名 1–2 个考虑过但排除的方法及理由（成本/时间/不匹配阶段）。
 编排：先做什么→再做什么，各步产出什么（参照场景打法；无贴合场景则通用兜底并标注）。]

## 四、样本与配额
[研究总体、抽样思路、样本规模与配额、招募与甄别要点。
 先读 methods/standards/sampling.md（运行时判断有无，见 SKILL.md 2.5）：
   · 能读到 → 按其条款写，并记其 status；样本量给估算依据而非凭空拍一个权威数字。
   · 读不到 → 给通用建议并就地标注「⚠️ 抽样规范（methods/standards/sampling.md）未找到，本段为通用建议、未经本库规范背书」。]

## 五、成本
[人力、时间、物资、渠道/激励等投入估算。]

## 六、时间规划
[分阶段排期（设计准备 / 招募 / 执行 / 分析 / 报告），每阶段留余地；
 标出关键风险点与应急预案（呼应坑五：方法/资源/时间的风险预见）。]

## 七、交付物
[最终交付什么：报告 / 结论建议 / 以及过程交付（如访谈提纲、问卷）。
 注：选定深访/问卷后，具体提纲/问卷可由对应生成器（如 generate-interview-guide）再产出，
 本方案只需说明交付形态，不在此堆问题。]

## 方案自检结果
[对照 research-project-workflow.md 的检查清单逐条回扫的结果，见下文第二节。]
```

写法约束：

- **方法段必须见"理由"**：选用与排除都给理由，体现这是权衡过的方案。
- **抽样段必须先读 `methods/standards/sampling.md` 再写**：能读到就按它写并记 status；读不到才给通用建议并带"未背书"标注（纪律 3 + 4）。不可凭空编样本量。
- 凡某段基于 draft 正典、或因无贴合场景而通用兜底，**在该段就地标一句**（如「⚠️ 本段方法编排无贴合场景打法，通用兜底」）。
- 研究内容、方法、交付三者要能对应得上（同一原始需求贯穿，呼应流程规范"报告/方案/提纲思路一致"）。

## 二、方案自检（对照清单回扫）

起草后拿运行时读到的 `research-project-workflow.md` 检查清单逐条扫，至少覆盖方案阶段这几条，逐条标 ✅/⚠️/❌ 并补缺：

```
## 方案自检结果
- [✅/⚠️/❌] 研究目的清晰，归类（探索/描述/解释）明确
- [✅/⚠️/❌] 研究内容对研究目的做了纵横拆解
- [✅/⚠️/❌] 研究方法服务于研究问题，选用/排除均有理由
- [✅/⚠️/❌] 抽样及配额已说明（已读 sampling.md：能读到则据其写并记 status；读不到才标"未背书"）
- [✅/⚠️/❌] 成本（人力/时间/物资/渠道）已估
- [✅/⚠️/❌] 时间排期留有余地，并预见了风险与应急
- [⚠️] 其余执行/交付阶段条目（督导分工、数据处理、报告延展性等）属落地环节，方案以"后续安排"带过
```

> 自检是实质修改：发现缺漏要回去补方案文本，不是打个勾走过场。

## 三、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实 brief 重写）

> 下例是凭空编的格式演示，不针对任何真实项目，方法名也仅为示意。看完格式即弃。

```
## 三、研究方法（选型 + 理由）
- 用户深访（toolbox/collection/interviews.md，status: draft）：会员"为什么用不上某权益"是动机/认知问题，需 why/how，深访最直接——覆盖研究内容①②。
- 满意度问卷（toolbox/collection/satisfaction-survey.md，status: draft）：要量化各权益的使用率与满意度做横向比较，问卷可规模化——覆盖研究内容③。
- 关键驱动分析（toolbox/analysis/key-driver-analysis.md，status: draft）：从问卷数据找"哪些权益体验最拉动整体满意度"，支撑改版排序。
- 排除：可用性测试——本次问题在"要不要用/感不感知"而非"界面好不好操作"，阶段不匹配，故排除。
- 编排：先 8–10 个深访摸清问题假设 → 再问卷验证与量化 → 驱动分析排序。（参照 product-experience/iteration 的评估诊断打法，status: draft）

## 四、样本与配额
（已读 methods/standards/sampling.md，status: draft；据其条款写）
深访：按信息饱和判停，高频/低频用权益各 4–5 人起步、不饱和再补；问卷：覆盖会员池分层配额，样本量按研究目的+置信水平+可接受误差+群体变异性估算并留痕（依 sampling.md），不预设固定数字拍脑袋。
⚠️ sampling.md status 为 draft，结论性数字口径待其定稿后复核。
```
> 注意上例如何让每个方法都挂在"覆盖哪块研究内容"上、如何写排除理由、如何把抽样规范的依据嵌进正文（此例为"规范可读到"的情况；若运行时确实读不到该规范，则改为通用建议 + "未背书"标注）——**形式照此，内容必须按真实 brief 重新生成**。
