# JD App Journey Map

## 定位

这是一个面向京东 APP 产品、设计和体验分析的复合型研究 skill。默认最终产出不是纯文字分析，而是一套可本地打开的 HTML 用户旅程图页面。目标不是生成通用电商旅程图，而是把输入场景转成：

1. 京东业务场景判断
2. 用户任务和决策问题
3. 目标用户分层
4. AI 模拟用户洞察
5. 用户旅程地图
6. 痛点、根因、机会点和指标影响
7. 后续验证建议
8. HTML 页面、关键图片和可视化交付物

默认用中文输出，先给结论，再给理由。面向非代码用户表达，用产品、用户、业务和设计语言说明问题。

## 何时使用

当用户提出以下需求时使用：

- 为京东 APP 某个页面、功能或链路生成用户旅程图
- 分析商详、搜索、推荐、评价、问答、购物车、下单、售后、内容流等场景
- 输入一个新功能或现有功能，要求做用户体验走查
- 输入要优化的指标，要求判断用户痛点、行为阻力和机会点
- 希望模拟不同目标用户的真实想法、访谈反馈、决策路径
- 希望产出用于汇报、Figma 画布、PRD、方案评审的 HTML 页面或可视化材料

## 不要用在这些情况

- 只需要评审一个还没上线的 before/after 页面方案：优先用 `prelaunch-usability-review`。
- 已经有 AB 实验数据、上线后涨跌或多版本数据复盘：优先用 `design-abtest-analysis`。
- 只需要改 HTML 视觉或排版：不要重跑本 skill，先做局部页面优化。
- 只有单个组件状态、没有明确用户任务链路：先补场景和任务，否则容易生成空泛旅程图。

## 最小输入

用户信息不足时也可以先推进，但必须明确假设。最小输入包括：

1. 页面或链路名称。
2. 用户要完成的任务。
3. 当前业务目标或想改善的指标。
4. 页面截图、流程截图或文字描述。

理想输入包括：入口、关键页面、结果页、弹层、异常状态、目标用户、品类、人群、已知问题、真实数据或调研材料。

## 核心原则

- 先定义用户任务，不直接按页面模块罗列功能。
- 先分层目标用户，再做旅程图；不要只写一个笼统用户画像。
- 明确区分事实、用户提供信息、模型推演和证据不足。
- 模拟用户调研只能用于假设生成和方案走查，不能冒充真实调研结论。
- 京东场景要关注交易决策、评价证据、价格/权益、履约、售后、信任和复购。
- 涉及 AI 能力时，要覆盖证据链、置信度、纠错、用户控制、隐私和兜底。
- 默认以 HTML 为核心交付物：除非用户明确只要文字，否则要生成本地可打开的 `index.html`。
- 页面关键部分应有视觉图表或生成图片；图片用于表达用户洞察、典型路径、想法汇总和最终用户地图，不用于无意义装饰。
- HTML 模板必须保留用户旅程自己的风格，不要套用可用性测试或 AB 分析模板。
- 页面重点是“用户如何一步步完成任务”，不是单页专家评审，也不是数据复盘。

## 默认工作流

1. **解析输入场景**
   - 页面/链路：商详、搜索、评价、问答、购物车、下单、售后、内容流等。
   - 功能状态：现有功能、新功能、改版方案、指标问题、竞品启发。
   - 用户动作：用户在什么页面、什么情况下、想做什么。
   - 目标指标：点击、转化、加购、下单、停留、使用率、复访、投诉、售后等。

2. **补全关键假设**
   - 如果信息不足但不影响大方向，直接给合理假设。
   - 如果缺失会改变结论，例如品类、人群、核心指标、页面入口，再提出 1-3 个关键问题。

3. **建立京东目标用户分层**
   - 默认拆 3-5 类用户。
   - 按购物任务、决策风险、价格敏感度、品类熟悉度、信任需求、时间压力、售后敏感度分层。
   - 如需详细模型，读取 `references/jd-user-model.md`。

4. **模拟用户调研**
   - 为每类用户模拟：任务背景、典型问题、关注点、担忧、触发购买/放弃的条件。
   - 需要深度调研时，按 Plan -> Scout -> Persona -> Interview -> Insight Chain 执行。
   - 如需方法细节，读取 `references/simulated-research-method.md`。

5. **生成用户旅程地图**
   - 默认使用阶段式表格。
   - 阶段按用户意图命名，不按内部系统步骤命名。
   - 每阶段包括：用户目标、行为、触点、想法、情绪、痛点、根因、机会点、指标、证据/置信度。
   - 如需完整模板或视觉画布结构，读取 `references/journey-map-template.md`。

6. **诊断痛点和根因**
   - 区分信息不清、决策成本高、信任不足、价格/权益不明确、流程阻塞、视觉干扰、履约/售后焦虑、AI 答案不可信等问题。
   - 如需评分，读取 `references/painpoint-priority-rubric.md`。

7. **输出优先级建议**
   - 分为：P0 直接影响核心转化、P1 明显改善体验和决策、P2 增强满意度或效率。
   - 每个建议要说明影响用户、影响指标、落地难度和验证方式。

8. **给下一步**
   - 给出数据验证、访谈问题、可用性测试、AB 实验、设计走查或 PRD 补充建议。

9. **生成 HTML 交付物**
   - 默认创建一个输出文件夹，包含 `index.html` 和必要的 `assets/`。
   - 可复制 `assets/html-template/index.html` 作为页面起点，再替换内容、图表和图片。
   - 页面必须把旅程分析可视化，不要只把 Markdown 粘到网页里。
   - 关键图像区包括：AI 模拟用户洞察图、典型用户决策路径图、想法汇总图、最终商详用户地图。
   - 生成 HTML 前必须读取并遵守 `references/html-style-contract.md`，它是 Codex、Claude、DeepSeek 等所有生成通道共用的固定视觉合约。
   - 如需 HTML 结构、视觉风格、图片生成规范，继续读取 `references/html-output-spec.md`。
   - 如果环境支持图片生成工具，优先为关键图像区生成 PNG/JPG 并嵌入 HTML；如果图片生成不可用，用高质量 HTML/CSS/SVG 图表替代，并在交付说明中标注。

## 证据标注规则

每个关键结论必须标注来源类型：

- **用户提供**：来自用户输入、截图、业务背景、数据、调研材料。
- **模型推演**：基于京东电商场景和用户行为逻辑推断。
- **待验证**：当前证据不足，需要真实数据、访谈或可用性测试确认。

置信度默认分为：

- **高**：用户提供了明确证据，或与已知链路强相关。
- **中**：推断合理，但缺少直接数据。
- **低**：只是待验证假设，不能作为结论使用。

## 京东场景提醒

电商旅程不要停留在“浏览-比较-购买”。京东 APP 场景通常要额外检查：

- 商品是否适合我
- 评价证据是否可信
- 问答是否覆盖我的问题
- 价格、券、补贴、会员权益是否清楚
- 配送时效、安装、退换修是否确定
- 店铺、品牌、自营、第三方责任边界是否清楚
- AI 结论是否有依据、是否允许追问和纠错
- 用户是否能控制记忆、推荐和个性化使用
