# 设计稿打标（内容标注 + 结构标注）

这个 skill 用来帮助 Codex 给设计稿添加或检查两类打标：**内容标注**（展示组件模块的构成）与**结构标注**（展示研发开发要的边距关系与模块细节）。

## 两类标注（先判断要做哪一类，或两类都做）

| 类别 | 解决什么 | 目的 / 受众 | 视觉形态 |
|---|---|---|---|
| **内容标注** | 展示**组件模块的构成** —— 这个组件由哪些模块组成、每个模块是什么 | 设计 / 评审：快速理解结构 | **引线 + 编号/字母标记（①②③ 或 A/B/C）+ 文字标签**，指向各模块，常配「模块清单 / 配置·限制」图例 |
| **结构标注** | 展示研发开发过程中要的**边距关系 + 各模块需展示的细节** | 研发：按结构精确还原布局 | **红/蓝双色标尺**（红=大维度·整体框架 / 蓝=小维度·元素细节），纯线条 + 端点 + 数值，数字不带单位 |

判断口诀：
- 用户说「**模块构成 / 组件由什么组成 / 解剖 / 每个部分是什么 / 标一下结构组成**」→ **内容标注**。
- 用户说「**边距 / padding / 间距 / 尺寸 / 标尺 / 研发还原 / 细节尺寸**」→ **结构标注**。
- 用户说「**完整打标 / 出一份规范打标**」或在写「基础结构&设计属性」规范页 → **两类都做**：先内容标注讲清「由什么组成」，再结构标注给出「各部分的边距与尺寸」。

两类都遵守同一套硬性要求：**基于真实 bounding box，不靠截图估算；总容器模式管理；输出机读 YAML 记录**。

> 历史定位：本 skill 初版只有「结构标注（标尺）」。结构标注的全部规则（颜色矩阵 / 方向 / 计算 / 约束 / 复核）仍以下文 + `references/ruler-annotation-spec.md` 为准。内容标注规则见下「内容标注」节。

## 什么时候使用

当用户提出以下需求时，使用本 skill（先按「两类标注」判断走哪一类）：

**内容标注**
- 标注组件 / 页面的**模块构成**（由哪些模块组成、每个模块是什么）
- 给「基础结构&设计属性」规范页做结构示意（A/B/C 引线 + 模块清单）
- 解剖一个业务组件，列出必有 / 可选模块

**结构标注**
- 给 Relay / Zero / Figma 设计稿做标尺打标
- 标注页面边距、组件 padding、组件间距、宽高尺寸
- 根据设计稿节点生成红 / 蓝双色分级标注（红=大维度 / 蓝=小维度）
- 检查已有标尺是否符合规范

**两类通用**
- 输出可复核的打标记录或打标报告

不要用于以下场景：

- 只做视觉点评，不涉及打标
- 创建无关的设计组件
- 仅凭截图估算尺寸、间距或模块边界
- 从 `design.md` 生成页面文档

## 你以后怎么用

你可以直接用自然语言说：

```text
用 ruler-annotation 帮我给这个 Relay 节点做标尺打标：<节点链接>
```

或：

```text
帮我检查当前设计稿里的标尺打标是否符合规范。
```

也可以不写 skill 名，只要说清楚“标尺打标 / 尺寸标注 / 间距标注”，Codex 就应该触发这个 skill。

- Relay / Zero / Figma 的节点链接或节点 ID
- 当前已选中的设计稿节点
- 包含节点坐标、尺寸、层级、可见性的本地设计 metadata

如果没有目标节点，Codex 必须先向用户要节点链接或请用户选中节点，不能凭空开始。

# 内容标注（展示组件模块的构成）

> 目的：把一个组件 / 板式**由哪些模块组成、每个模块是什么**讲清楚，供设计 / 评审快速理解结构，也是「基础结构&设计属性」规范页里「结构示意」那张图的做法。

## 何时做内容标注

- 用户要「标一下模块构成 / 组件由什么组成 / 解剖这个组件 / 每个部分是什么」。
- 写业务组件规范页的「结构示意」段（A/B/C 引线 + 模块清单 + 配置·限制）。
- 需要在真实组件实例上叠一层「这是什么」的说明层。

## 构成（三件套：标记 + 引线 + 标签）

每个模块一组：

| 元素 | 说明 | 样式 |
|---|---|---|
| **标记 marker** | 编号 `①②③…` 或字母 `A/B/C…`，贴在或紧邻被标模块 | 直径 16–20 圆形 badge，填 `color_primary` 红或中性深灰，白字；或纯文字编号 |
| **引线 leader line** | 从标记 / 模块边缘连到标签，最短直角或直线 | 1px solid stroke，浅灰 `#8D9199` 或随标记色；可省略（标签贴近模块时） |
| **标签 label** | 模块名（+ 可选「配置：必有/可选」「限制：字数/数量」） | PingFang SC，模块名 16 Semibold `#11141A`，说明 14/16 Regular `#8D9199`（双色，同结构规范页） |

> 编号顺序：按阅读动线（左→右、上→下）给模块编号，与「模块清单 / 配置·限制」图例的顺序一致。

## 落点规则

1. **标记贴模块、标签外置**：标记叠在模块上或紧邻（≤8px），标签 / 清单放组件外侧（右侧或下方留白），引线连接二者；不要把整段文字压在组件内容上。
2. **引线最短、不交叉**：同一侧的引线尽量平行、不打架；标记编号顺序与清单顺序一致。
3. **基于真实 bounding box 定位**：标记中心、引线端点都用模块节点的 `absoluteBoundingBox` 算（marker 中心 = 模块中心或某个角；引线起点 = 模块边缘、终点 = 标签左缘），**不靠截图估位**。
4. **模块粒度**：只标「需要被认知的功能模块」（如 头像区 / 关注按钮 / 价值面额 / 业务标签），不标到原子图层（描边、单个 vector）。可选模块在清单里标「可选」。
5. **真实例优先**：内容标注叠在**真实组件实例**上（沿用 relay-spec-longpage 复用实例原则），不伪造示意图。

## 与结构标注的配合（组件解剖 / 规范页 §03）

一个组件要**同时**出内容标注 + 结构标注时（如规范页「基础结构&设计属性」），**复制要标注的组件模块成两份独立实例，一份只做内容标注、一份只做结构标注 —— 不要把两类叠在同一实例上**（引线+编号 与 盒型色块叠一起会互相糊，读不出来）。两份并置（上下或左右）：

| 份 | 做什么 | 怎么画 | 回答 |
|---|---|---|---|
| 份①·内容标注 | 组件由哪些模块组成 | 组件实例 + ①②③ 引线 + 模块清单 | What（这是什么模块） |
| 份②·结构标注 | 各模块的边距 / 间距 / 尺寸 | 组件实例 + **盒模型色块（模式 B）** + chip 数值 | How much（多少） |

- **本场景结构标注用盒模型色块（模式 B）**呈现：半透明色块铺间距区（像 DevTools，红大 `@0.30` / 蓝小 `@0.15`）；盒型表达不了的元素尺寸（整卡高 / 图标 W×H）用线标尺补两侧。见「两种呈现模式」。
  > **作用域**：这是「组件解剖 / 规范页配合产出」的约定。**单独研发交付**的结构标注仍以 **A 线标尺**为默认（B 可选）。
- 两份实例的**编号 / 模块名必须一致**（份① 的 ① ↔ 份② 同一模块），便于交叉对照。
- 内容标注回答 **What**，结构标注回答 **How much**。

## 内容标注 YAML 记录

```yaml
content_annotations:
  - id: module-A
    marker: "A"           # 或 "①"
    module_name: "头像区"

    target_node_id: "684:3914;464:4927"
    marker_geometry: { x: 0, y: 0, width: 18, height: 18 }
    source: bounding_box
```

# 结构标注（边距 / 尺寸标尺）

> 以下全部为**结构标注**的规则与落地（标尺：外边距 / padding / 间距 / 尺寸）。详细规则以 `references/ruler-annotation-spec.md` 为准。

## 总容器模式（推荐输出格式）

当用户要求"整洁"或"放在总容器"时，必须使用**总容器模式**，而不是把标注散放在页面上。

### 默认模式（无标题、无填充色块）

用户无特殊要求时，采用简洁版：标注直接叠放在设计稿组件坐标范围上，总容器仅作为管理容器。

```
Frame「标尺标注/<nodeId>/<组件名>」
  无填充、无描边、clipsContent=false
  └── Frame × n「标尺」— 纯线条 + 端点 + 数值，叠放在组件坐标范围内及周边
```

**总容器定位算法（无标题版）：**
```text
PAD = 50  // 四周各留 50px 容纳外侧标尺

CONT_X = 组件.x - PAD
CONT_Y = 组件.y - PAD
CONT_W = 组件宽 + PAD * 2
CONT_H = 组件高 + PAD * 2

// 标尺位置用绝对坐标算好后，转换为相对容器：
child.x = abs_ruler_x - CONT_X
child.y = abs_ruler_y - CONT_Y
```

**⚠️ 重要**：总容器与设计稿组件是**页面同级兄弟节点**，不是父子关系。标注叠在组件之上，在 Relay 画布中可见，截图单独截取总容器会显示透明背景，属正常现象。

### 标尺子 Frame 内部布局

**水平标尺**（宽 = 被测距离，高固定 12px）：
```
标注线   x=0,   y=6,  w=被测距离, h=1  constraints: H-STRETCH, V-CENTER
左端点   x=0,   y=0,  w=1, h=12        constraints: H-MIN, V-STRETCH
右端点   x=w-1, y=0,  w=1, h=12        constraints: H-MAX, V-STRETCH
数值文字  x=居中, y=-(fontSize+2)（上方）或 y=14（下方）
```

**垂直标尺**（高 = 被测距离，宽固定 12px）：
```
标注线   x=6,   y=0,  w=1, h=被测距离  constraints: H-CENTER, V-STRETCH
上端点   x=0,   y=0,  w=12, h=1        constraints: H-STRETCH, V-MIN
下端点   x=0,   y=h-1, w=12, h=1       constraints: H-STRETCH, V-MAX
数值文字  x=-(textWidth+2)（左侧）或 x=14（右侧），y=垂直居中
```

### 颜色精确值（双色 · 现行约定）

> ⚠️ **现行只用两色，绿色废弃**。按**层级**分（整体框架 vs 元素细节），**不是**按"尺寸 vs 间距"，也**不是**按数值大小。例：同是 16px，外边距→红（大），元素间距→蓝（小）。

| 维度 | 含义 | HEX | RGB(0–1) |
|---|---|---|---|
| **大维度** | 整体框架：整条/整卡高宽、外边距、主区块间距（主内容↔操作区、主图↔内容区）、主图等主结构元素尺寸 | `#FF0F23` 红 | `{r:1, g:0.0588, b:0.1373}` |
| **小维度** | 元素细节：单元素尺寸、相邻元素小间距、行间距、图标/标签间距 | `#0C82F7` 蓝 | `{r:0.0471, g:0.5098, b:0.9686}` |

- 数字**不带单位**（裸整数；尺寸写 `W×H`，如 `36×36`）。
- 纯 1px 线 + 端点 tick + 数值；**无外框矩形、无四角圆角标记、无填充蒙层**（这些是参考稿的装饰加强版，默认不套用）。
- 文字：PingFang SC Semibold 12，颜色随维度（红/蓝）。

### 间距拉通（尺寸链）

同方向的间距（**含外边距**）别分散在上/下或多层 —— 尽量**落到同一条基准线**，连成一条尺寸链，比对最直观：

- **横向间距**（左右边距 + 模块间横向 gap）→ 卡片**下方一条水平基准线**，左→右依次排开。
- **纵向行间距**（内容行之间的 gap）→ 内容区**右侧一条竖直基准线**，上→下依次排开。
- 每段：颜色随大/小维度（红/蓝）的尺寸线 + 端点 + 数值；并用**浅灰引出线**（`{r:0.7,g:0.71,b:0.74}`，1px）从被测模块边连到基准线，把每个值锚到它量的那条边。
- 尺寸标注（元素自身宽高）另置上方/两侧，与"间距链"分区，互不干扰。

### 两种呈现模式：线标尺 / 盒模型色块

结构标注有两种画法，按需选，也可合并：

| 模式 | 形态 | 适合 | 填充 |
|---|---|---|---|
| **A 线标尺**（默认） | 1px 线 + 端点 tick + 数值，间距拉通到基准线 | 研发精确还原、干净 | 无填充（硬性要求 6/7） |
| **B 盒模型色块** | 半透明色块铺满 padding/间距区 + chip 数值 | 评审一眼看懂「哪段空多大」，像 DevTools 盒模型 | 半透明填充（**本模式专用，是硬性要求 6/7 的明确例外**） |

**合并用法（推荐）**：间距用色块(B)，色块表达不了的元素尺寸（整卡高 / 模块高 / 图标 W×H）用线标尺(A) 的竖/横标尺补在两侧，合进同一个容器。

#### 盒模型色块模式（B）规格

- **只填「空」的区域**：四边 padding 环（上/下/左/右边距）、主区块间距、行间距；**模块内容本身不填**（留白透出底稿）。区域互不重叠（padding 环与 gap 带相邻不叠）。
- **不透明度分层级**（用深浅区分大小维度 —— 别再加斜纹/描边，斜纹试过已弃用）：
  - **大维度** 红 `#FF0F23` @ **opacity 0.30**（整体框架，更实、跳出来）
  - **小维度** 蓝 `#0C82F7` @ **opacity 0.15**（元素细节，更淡、退后）
- **数值用 chip**：实色圆角小盒（`cornerRadius 3`、内边距 5×2、底色 = 该维度纯色 opacity 1）+ **白字** PingFang SC Semibold 11，居中压在色块上 —— 比裸数字直观。
- **尺寸线**：整卡高 / 模块高 / 图标尺寸等色块表达不了的，用细线标尺（vline/hline + 端点 + chip）放左侧/两侧，与色块分区。
- 容器仍是**页面同级透明兄弟**叠在真实组件上；几何全部来自 `absoluteBoundingBox`。

## 已知陷阱与修复记录（Gotchas）

### 标注重叠问题

**场景：** 多个标注共享同一侧（左侧或右侧）时，容易在画布上堆叠重合，数字互相压盖无法阅读。

**根本原因：**
- 左侧标注（G1/G2 大尺寸垂直 + B2 小尺寸垂直）默认使用相同或相近的 x 偏移，导致重叠。
- 右侧标注（多条小间距垂直标注 + 外框总高标注）同理。
- 小数值标注（如 5px）若直接放在边界贴合位置，容易与相邻标注或卡片内容重叠。

**强制规则：**
1. **同侧多条标注必须分层错开 x 偏移**：
   - 左侧首选层：大尺寸结构性标注（如封面高/信息区高）放在 `relX = -40` 以外。
   - 左侧次选层：小尺寸辅助标注（如标签顶部 padding）放在 `relX = -12 ~ -16`。
   - 右侧首选层：总高等大尺寸标注放在最外侧（`relX = card_width + 20` 以上）。
   - 右侧次选层：小间距标注放在 `relX = card_width + 8`。
2. **5px 等极小值标注不能放在卡片外边界**，必须放在被测元素附近的内侧区域，沿被测行的垂直中心对齐。
3. 脚本执行完毕后必须调用 `get_design_metadata` 或脚本查询，逐一核对每条标注的 `relX` / `relY`，确认无两条标注 x 差值 < 12px 且 y 区间重叠。

**5px 话题信息 padding_left 的正确摆放示例：**
```text
错误：放在 relX=-8（卡片左边缘外），与左侧垂直标注区域堆叠。
正确：放在 relX=0（卡片左边缘），y 对准话题信息行内部（relY = 话题条 y + 10），
      文字标注在下方，不压住内容。
```

### ⚠️ Relay use_design_script 落地铁律（务必照做，血泪教训）

1. **每个 `relay.create*()` 节点都必须 `appendChild` 到目标容器** —— 漏 append 的节点会被自动挂到 page 原点 `(0,0)` 成游离污染。顺序：先 `appendChild`、再设 `x/y`（reparent 不会自动重置坐标）。
2. **页面上下文极易踩坑**：`use_design_script` 每次调用都把 `relay.currentPage` 重置；`getNodeByIdAsync` 和 MCP 读取/截图都**相对"客户端当前打开的页"**解析。
   - **开局一次**：用 `getNodeByIdAsync(目标)` 拿到节点 → 向上 `.parent` 走到 `type==='PAGE'` → 记下**工作页 id**；之后每个脚本开头 `await page.loadAsync(); await relay.setCurrentPageAsync(工作页)` 复用这一个 id。
   - **绝不为了"找节点"去遍历所有页 `setCurrentPageAsync`** —— 这会把客户端切走，之后所有 MCP 读取/截图、`getNodeByIdAsync` 全部「找不到」，且很难自动恢复（往往得请用户点回工作页）。
3. **`.parent` 不一定是 page**：目标节点的父级可能是 GROUP / FRAME（卡片常嵌在某个组或规范页里）。建"兄弟标注容器"要挂到**真正的 PAGE**（向上找 `type==='PAGE'`），否则会塞进别的组、污染它，坐标也乱。
4. **对齐校验走数据层**：读回每条主线 `absoluteBoundingBox`，确认起止 == 被测模块真实边界。**别只信截图**：Relay 截图按 node id 缓存、会滞后，且**不合成兄弟节点**（透明标注容器单独截图只见标尺线、看不到底稿，属正常）。
5. **竖线**：`createLine().resize(len,0)` 后 `rotation=90`；定位 `l.x=左边界, l.y=顶边界+len`（旋转后 bbox 向上延展）。横线无旋转，`l.x/l.y` 即 bbox 左上角。
6. **几何统一用 `absoluteBoundingBox`**：metadata 的子节点 x/y 相对父节点，跨层直接相减会错。

## 硬性要求

执行时必须遵守：

1. 所有尺寸和间距必须来自真实节点 geometry 或 bounding box。
2. 禁止根据截图目测或估算数值。
3. 做减法前，必须把相关节点换算到同一坐标系。
4. 默认过滤 hidden、locked 和非视觉辅助节点。
5. 优先复用现有标尺母版或规范中记录的变体；如果当前稿件中找不到标尺母版，允许严格按 `references/ruler-annotation-spec.md` 记录的文字、线条、颜色、端点和约束样式重建等价标尺组件。
6. （**线标尺模式 A**）尺寸标注只需要线和端点，不允许添加测量填充蒙层、遮罩条、半透明背景或容器描边。**盒模型色块模式 B 是本条的明确例外**：它就是用半透明色块铺间距区（见「两种呈现模式」），但色块严格只铺「空」区、用不透明度分层、不加斜纹/描边。
7. 标注线和端点必须使用线条描边表达，不得用填充矩形模拟；线条宽度固定为 1px。
8. 标尺父容器必须无填充、无描边，并可手动横向 / 纵向拉伸；端点必须贴边，标注线必须随父容器尺寸自动伸缩，遵循 2.2 和 2.3 的可变与约束规则。
9. 不允许偏离规范中记录的标尺颜色、字号、字重、线宽、线型、端点样式和约束方式。
10. 只标注对复现布局有价值的关系，避免把画面铺满标尺。
11. 只用红/蓝两色（红=大维度、蓝=小维度，按层级分，绿色废弃）；空间不足时优先保留红色（大维度），次要的小维度蓝色标注可降级为报告文字说明。
12. 标注文案必须可读，不能遮挡核心内容。
13. 生成或检查标注时，必须同步输出机器可读记录。

遇到以下情况必须停止并说明原因：

- 无法读取真实节点几何信息。
- 找不到目标节点。
- 找不到或无法合理识别标尺母版变体，且无法根据 `references/ruler-annotation-spec.md` 重建等价标尺样式。
- 节点坐标系不一致且无法换算。
- 用户要求仅凭截图估算并打标。

## 标注颜色层级（双色：红=大维度 / 蓝=小维度）

按**层级**选择颜色（不是按"尺寸 vs 间距"，也不是按数值大小）：

- **红 `#FF0F23`（大维度·整体框架）**：整条/整卡高宽、页面/组件外边距、主容器 padding、主区块间距（主内容区↔操作区、主图↔内容区）、主图等主结构元素尺寸。
- **蓝 `#0C82F7`（小维度·元素细节）**：单元素尺寸、相邻元素小间距、行间距、图标与文字/标签之间、装饰性细节。
- 同一数值可因层级不同而异色：外边距 16→红，元素间距 16→蓝。

生成优先级：

1. 整体框架边距与主区块间距（红）
2. 主结构元素尺寸（红）
3. 元素间小间距、行间距（蓝）——优先「拉通」到同一基准线
4. 单元素尺寸细节（蓝）
5. 重复间距只标一个代表样本，并在报告中说明重复规则

## 执行流程

1. 解析目标链接或当前选中节点，识别 `fileKey`、`pageId`、`nodeId`。
2. 通过可用设计工具读取目标节点树、截图和 metadata。
3. 找到或识别标尺母版，以及方向 / 颜色变体；若不存在母版，则按规范中的视觉样式重建等价标尺组件。
4. 将相关节点 bounding box 统一到同一坐标系。
5. 识别页面级、模块级、组件级结构。
6. 基于 bounding box 计算外边距、padding、间距和关键尺寸。
7. 按红 / 蓝双色层级（红=大维度 / 蓝=小维度）选择最小但足够表达结构的标注集合；同方向间距尽量「拉通」到同一基准线。
8. 从标尺母版复制实例；若无母版，则创建符合规范样式的等价标尺实例。设置方向和颜色，拉伸父容器，并更新数值文本。
9. 避免遮挡核心内容和已有标注。
10. 输出 YAML 标注记录和简短中文报告。
11. 环境支持时，截图复核视觉结果。

## 计算规则

读取 bounding box：

```text
left = node.x
top = node.y
right = node.x + node.width
bottom = node.y + node.height
width = node.width
height = node.height
```

统一坐标系后再计算：

```text
gap_x = next.left - current.right
gap_y = next.top - current.bottom
padding_left = child.left - container.left
padding_right = container.right - child.right
padding_top = child.top - container.top
padding_bottom = container.bottom - child.bottom
size = width x height
```

数值格式：

- 整数：直接输出整数。
- 精确 0.5 像素：保留 `.5`。
- 小数误差小于 `0.1`：四舍五入为整数。
- 其他小数：保留 1 位小数，并在报告中标记 `非整数间距`。

## 输出格式

生成打标时，输出：

- 已标注的内容
- 被跳过或降级为文字说明的内容
- 阻塞点或前提假设
- YAML 标注记录
- 截图复核状态，如果环境支持

YAML 记录格式：

```yaml
annotations:
  - id: annotation-001
    level: outer
    color: red
    direction: right
    value: 20
    unit: px
    target:
      from_node_id: "node-a"
      to_node_id: "container"
      relation: padding_left
    geometry:
      x: 0
      y: 0
      width: 20
      height: 20
    source: bounding_box
    confidence: high
```

检查已有标尺时，输出：

```text
结论：通过 / 有风险 / 不通过
发现项：
- [级别] 问题描述
修复建议：
- 建议动作
复核清单：
- 数据来源
- 颜色层级
- 样式一致性
- 方向与可读性
- 数量控制
- YAML 与画布一致性
```

## 完成前复核

最终回复前检查：

- 每个数值都来自 bounding box。
- 红 / 蓝双色与大/小维度层级匹配（红=整体框架、蓝=元素细节；绿色不再使用）。
- 数字不带单位；无外框/四角/填充蒙层；同方向间距已尽量拉通到同一基准线。
- 标尺实例保留母版视觉样式；无母版时与规范记录的纯线标尺视觉样式和约束方式一致。
- 方向和文字位置可读。
- 没有遮挡重要内容。
- 重复间距没有过度标注。
- YAML 记录和画布结果一致。
- 非整数或不确定数值已明确说明。
