# 抢单大厅场景生成 Skill

设计师说人话 → 生成真实订单数据 → Zero 里画出高保真抢单大厅页 → 实测校验还原度。

**产物是 Relay 可编辑图层（use_design_script 纯绘制，自包含），非 HTML。**

## 依赖的本目录资产（同级文件，务必先读）

```
抢单大厅/
├── components/订单卡片.md        零件规格:23模块×5类卡片矩阵 + 视觉细则(标签/字体/距离/按钮…)
├── components/全局顶部导航.md    顶部132黑底(状态栏+导航+tab)
├── components/底部Bar.md         底部94白底(接单设置+刷新/开工)
├── icons.md                      所有图标京东CDN(含状态栏信号/wifi/电量)
├── 页面搭建规则.md               页面骨架+两条联动+§4映射词典+§6.5脚本铁律
├── 地址距离生成规则.md           随机生成商家/POI/距离/脱名的字段规则
└── scripts/                      draw-helpers.js + page-*.js + postprocess.js + ds.py
```

## 触发
- `帮我生成订单卡片` / `生成抢单大厅` / `画接单/到店/取货/送达/返还页` / `骑手APP抢单场景`
- 直接描述:"画3个1对1急送单的接单页,已开工,商家用潮界"

## Phase 0 · 解析需求（口语 → 参数）

抽成参数表，用 `页面搭建规则.md §4 自然语言→组件映射词典` 映射。**未指定项全自动填默认/随机**，不反问（除非描述自相矛盾）：

| 参数 | 取值 | 默认 |
|---|---|---|
| 页面 | 接单/到店/取货/送达/返还 的子集 | 见下铁律 |
| 订单类型 | 帮送/帮买/直送/1对1急送/预约/转单/强派 | 帮送 |
| 订单数量 | 每页卡片数 | 1 |
| 开收工 | 已开工/已收工 | 已开工 |

> ⚠️ **页面范围铁律（务必遵守，之前漏过）**：设计师说「**生成订单卡片流程 / 订单卡片流程 / 生成订单卡片**」= **必须生成接单+到店+取货+送达+返还 全 5 个场景页**（一个订单贯穿 5 环节）；只有明确说「只画接单页 / 画送达页」这类**单指某页**时才生成子集。**默认按 5 场景全出，不要只画接单页**。
| 商家 | 指定名 / **随机真实店名** | 随机 |
| 贯穿模式 | 一单贯穿多页 / 每页独立多单 | 多页→贯穿；单页→独立 |

## Phase 1 · 场景规划（两条联动铁律）

按 `页面搭建规则.md §3`：
- **开收工 → 底Bar**：已开工↔刷新 / 已收工↔开工。
- **tab → 卡片类型**：接单↔新任务tab / 到店·取货↔待取货tab / 送达↔配送中tab / 返还↔返还。
- **tab 数字 = 卡片数（§3.3）**：每个环节页的 tab 数字必须等于该页画的卡片张数（待取货N↔N张、配送中N↔N张）；**新任务 tab 恒无数字**。生成前先定每环节卡片数，再同步 `mkNav` 的 tab 文案数字。

输出「页面清单」：每页的 tab（含数字）、卡片类型、底Bar 形态、卡片数、x 偏移。

## Phase 2 · 生成真实订单数据（真实感的关键）

按 `地址距离生成规则.md` 为每单生成：
- 真实商家名 + POI 取货地址 + POI 送达地址（同城不同点）
- 脱名收货人（姓+\*）+ 脱敏手机号（前3后4）
- 距离（起点100-900m/终点1-5km，按单位换算：≥1000m→km 保留1位小数）
- 价格 + 货品（7类品类之一：食品小吃/超市/水果生鲜/医药/便利店/个人/饮料）+ 时效
- 活动标签 / 属性标签（按订单类型合理配）

> ⚠️ **贯穿一致性**：同一订单跨页时，商家/送达地址/小票号/距离/准时奖 T·N **全程锁定一致**（急送单准时奖标签「T 前未送达少 ¥N」= 接单其他费用「含 T 前送达奖励 ¥N」，同一 T/N）。

## Phase 3 · 绘制（调 scripts/）

1. 确认 MCP 通路（`127.0.0.1:27618`）+ **Zero 桌面端已打开目标文件**（写入当前打开文件）。
2. 把 Phase 2 数据填入 `scripts/page-*.js` 的文案位。
3. 逐页：`cat draw-helpers.js page-X.js > run.js && python3 ds.py run.js`。
4. 每页跑 `postprocess.js`（`__ROOT__`→pageId，字体/间距修正）。
5. 多页横向排开（x 偏移，每页宽 375 + 间隔）。

> **必守 `页面搭建规则.md §6.5 脚本绘制铁律**：createFrame 默认 itemSpacing=10 要清零 / resize 后再设 AUTO / async builder 必 await / icon 全真实 CDN 禁占位。

## Phase 4 · 校验还原度（强制，mismatch≠0 自动修正重画）

逐节点实测，与 `components/*.md` 规范比对：
- 卡片 360/r12、按钮 44/r8、导航 132、底Bar 94、系统bar 34
- 标签描边 0.5px、数字字体 JDZhengHT-Bold、货品圆角 4
- **icon 占位残留必须 = 0**（无灰矩形/字符占位）
- 间距（距离3组件/内容列gap6/头部分组）、字重（刷新Regular/快捷电话Semibold）

**mismatch ≠ 0 → 自动定位差异、修正脚本、删页重画，循环直到 mismatch = 0 才交付**。不把偏差丢给设计师。

## Phase 5 · 验收产出

- 截图每页 + 一句话说明（生成了什么订单、几页、什么状态）。
- 报告实测结果（关键尺寸 + 还原度 mismatch=0）。
- **停**，不自动做别的。

## 还原度命脉（3 条，不可妥协）

1. **脚本内置实测值**：`draw-helpers.js` 的间距/圆角/icon 都回源稿 `1754061905668022274` 页 `2277:2` 逐节点实测，不脑补。
2. **回源稿实测优先于 md 文字**：任何尺寸/分组/icon 拿不准，读源稿节点实测；实测与 md 冲突则以实测为准并回写 md。
3. **Phase 4 强制实测 + 自动修正**：生成后必量，mismatch≠0 不交付。

## 边界
- 只画抢单大厅这 5 类页；其他页面不在范围。
- 产物是 Relay 图层，不出 HTML、不出真实摄影/3D/动效。
- 依赖 Zero 桌面端打开目标文件 + 本地 zero-design MCP 存活。
