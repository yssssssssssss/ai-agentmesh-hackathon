# 场域设计执行编排 —— PRD → 设计稿

> 这是本部门资源库的**可执行入口**。目标：接到一个交易场域的 PRD 或生成/改动需求，按四步方法论走到 ZERO/Relay 设计稿。
> 结构原则：**共享底座定规矩（读本地方法论 + 读 coding 零件），场域自包含四步（各写各的差异）**。
> 资源库根：`~/Documents/场域设计AI架构/平台交易设计部/`（需 `request_cowork_directory` 授权后访问）。
> 共享底座索引见 `_共享底座/SKILL.md`；coding 零件读取见 `_共享底座/coding-foundation读取指南.md`。

## 三条铁律（贯穿全程）

1. **缺输入先追问，绝不假设**——尤其现状、必须保留、合规约束。
2. **测不准的不写成事实**——精确 hex/间距/未实测规格标「推断/需确认」，进交付第 5 段。
3. **碰主流程不自动改**——命中场域 `3-转译为结构/主流程边界.md` 的，汇总交人拍板。

---

## Step 0 —— 过输入门（必做）

读 `_共享底座/输入SOP.md`，完成三件事：**判类型 → 备五项输入 → 过校验门**。

- **判类型**：A 新场域从零 / B 已有场域整页生成 / C 局部改动·PRD 驱动。判不准按更重的处理（A>B>C）。
- **五项通用必填**：①改动依据(PRD/需求)②现状(node id/截图 或「从零生成」)③改动目标④必须保留⑤上线约束(端/版本/字号/灰度/合规)。
- **校验门**：任一项缺 → **立即追问，不进入四步、不假设默认值**。

> 若 PRD 是文件/链接，先归档到该场域 `1-确定场域任务/_输入源/prd/YYYY-MM-DD-需求名.md`。

## Step 1 —— 三跳路由 + 扫错误案例

1. **认业务线**：`交易链路/`(购物车/结算/收银台/成功页/地址) ｜ `店铺/`、`权益中心/`(占位)。
2. **认场域**：进该场域目录，读 `场域元信息.md` 认边界；新场域整份复制一个已建空骨架场域（如 `交易链路/成功页/`）到目标业务线下、改名填内容。
3. **认阶段**：进场域 `SKILL.md`，按输入类型定四步起点。
4. **扫错误案例**（执行前必做）：先看 `_共享底座/错误案例总库/` + 本场域 `错误案例/`，命中触发条件的先规避。

## Step 2 —— 走四步

> **四步之上**贯穿判断标准（`_共享底座/0-判断标准/judgment-criteria.md`：务实/自然/包容/焕新）；**四步之下**接 AI 闭环（`_共享底座/AI闭环工作流/`）。
> 按输入类型选起点：**A 从①起 1→2→3→4；B 复用①②、直接 3→4；C 先走改动工作流分类，多数落 3/4 局部补丁**。

### ① 确定场域任务（不谈视觉）
读场域 `1-确定场域任务/`（方法.md / 任务分类框架.md / 场域任务.md）。想清「用户为何来到本场域、核心/次要/延伸/异常任务分别是什么」。B/C 类型可直接复用已沉淀的 `场域任务.md`。

### ② 建立认知模型（**只读作参考，不重新生成**）
读场域 `2-建立认知模型/认知模型.md`。购物车为 **v0.3 合并版**，两层结构：
- **Part A 元素关系库（权威·以 v0.1 静态图谱为准）**：71 节点 / 109 关系三元组，客观、不做强因果（"规则约束"不预设决定/计算/校验方向）。A3 节点目录 + A4 关系总表是**唯一权威数据区**。
- **Part B 执行规范（自 v0.2，溯源改指 Part A 节点）**：统一标准约束 / 决策心理链与动线 / 任务·交互执行层（待结算集合·核价·结果·机会·行动，v0.1 图谱不收的任务层）/ 出入口契约 / 交付库③清单 / 完整性三道门。
- **附录 表现层投影表**：全量商卡元素级绑定，溯源已指向 Part A 节点 ID（未建模项标「v0.1 未建模·应用层/待确认」）。
- **本步不产出、不改写认知模型**——它是③的**输入契约**。除非用户明确要求更新，否则只读取、引用。改动时守分工:元素/对象/状态/关系改 **Part A（且以 v0.1 图谱为准）**；出稿驱动逻辑改 **Part B**。
- 其余场域若为空骨架，且本次是 A 类型新场域，才按 `方法.md` 补建——并**先跟用户确认**再动。

### ③ 转译为结构（认知 → 稳定组织规则）
读场域 `3-转译为结构/`（结构六要素.md / 结构规则.md / 主流程边界.md / 交互与路径.md / 整页试跑配置.md）。
- 把②投影成结构：**Part A 状态节点（A3.3）**→逐态覆盖；**Part A 关系三元组 + 规则影响视图（A4/A5）**→联动反馈（受同一规则牵动的元素一起刷新）；**认知链顺序（Part B B2 主线）**→信息层级/视觉优先级；**触发支线（B2）**→条件显隐；**任务·交互执行层（B3）**→勾选/集合/核价就绪/控件/机会楼层；**出入口契约（B4）**→主流程边界。
- **交互规则**参考 coding `foundations/交互规范/`。
- C 类型：先按 `_共享底座/AI闭环工作流/改动工作流.md` 做**拆分→定位→分类→置信度**；命中 `主流程边界.md` 的不自动改。

### ④ 落实设计（调 coding 零件 + 写本场域差异）
- **设计系统 token**：AI 优先读机器源 coding `foundations/tokens/`（`tokens.json`/`tokens.css` + 扁平 `color/radius/spacing/typography.md`）；设计师文档版在 `foundations/设计语言基础（Design Tokens）/`、`foundations/视觉规范/`。
- **组件规范**：读 coding `foundations/基础组件库（功能型组件）/`（功能型·权威）、`foundations/业务组件库（业务型组件）/`（业务型·权威）——**英文 `components-*` 是残缺镜像，勿用**；场域专属楼层读 `foundations/场域特性规范/购物链路/<场域>/<组件>/bundle/{spec,variants,behaviors}.md`。
- **资源图标**：读 coding `foundations/assets/`；场域私有未收录的查本地 `_共享底座/资源assets/assets.md`。
- **场域私有组件**：本场域 `4-落实设计/组件/` 与 `视觉与变体.md`。
- 读取方式一律见 `_共享底座/coding-foundation读取指南.md`（coding.jd.com / project 912418 / SSO）。

## Step 3 —— 出稿（ZERO/Relay 构建配方）

参考 `_共享底座/搭建配方.md`，顺序 **能克隆就别重画 → 克隆不到再实例装配 → 都没有才从零搭**。

1. **勘察**：编辑前先用 ZERO MCP 工具（`get_design_metadata`/`get_screenshot`）看当前文件与目标节点。
2. **写入前加载规范**：用 `use_design_script` 前，先按 MCP 指引加载 `use-design-script` skill/资源；用 `use_design_html` 前加载 `use-design-html`。
3. **按名称发现资产**（不硬编码 id，**id 会漂移**）：遍历页面按名称找整页样例 / 组件集，命中程度决定走克隆 / 实例化 / 从零。
4. **测量类规则先跑再决定容器**（overflow、行宽等），勿按状态名臆断。
5. **逐态覆盖**：③给出的状态清单每个都要有稿或说明。
6. **验证**：`get_screenshot` 校验；高/不稳定节点用 `use_design_script` 遍历结构验证。
   - 通用陷阱：克隆大帧后别同段深度遍历 return（超时，拆两段）；每段脚本 `currentPage` 会重置，开头显式 `setCurrentPageAsync`；追加含文本实例前按最小子树预加载字体。

> 已有专属成熟 skill 的场域优先用它：**地址** → `/address-list-page-16.0`（含地址卡片 ground-truth、overflow rule、构建配方）。本编排负责其余场域与跨场域统一流程。

## Step 4 —— 交付 + 回流

- 按 `_共享底座/AI闭环工作流/交付模板.md` **五段交付**（做了什么 / 结构依据 / 覆盖的状态 / 截图 / 需确认项）。
- 门校验：门①覆盖（②×状态都有元素承载）、门②溯源（每个元素指得回认知模型某原语）、门③契约闭合（跨链路产/销匹配）。
- 实测/校准结论按 `_共享底座/AI闭环工作流/规则回流.md` 回写，记入场域 `change-log/`；**通用坑**升级到 `_共享底座/错误案例总库/`。

## 现状与边界

- **购物车**：认知模型成熟（v0.3 合并版 = v0.1 静态图谱权威底座 + v0.2 执行规范 + 全量商卡投影附录），四步可全程跑通。
- **结算 / 收银台 / 成功页**：四步为空骨架，A 类新建需先补①②（先与用户确认）。
- **地址**：另有成熟专属 skill `/address-list-page-16.0`，本编排遇地址直接转交。
- 本 SKILL 及整个资源库**将维护上 coding 平台**供全员使用——所以：文件用相对引用、零件读 coding、不在本地硬编码易漂移值。
