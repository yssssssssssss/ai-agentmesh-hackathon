## 一、访谈提纲骨架

固定三段式：**开场/暖场 → 主问题模块（若干）→ 收尾**。

### 开场 / 暖场

```
【开场白】
- 自我介绍 + 访谈目的（一两句，简明）
- 时长、形式、是否录音/录屏（征得许可）
- 减负说明：问题无对错，好坏评价都有价值，研究者不会因负面意见受伤；资料保密 / 匿名
- 暖身问题 1–2 个（轻松、客观、开放，帮受访者进入状态）
```
> 减负说明与暖身的具体写法依据运行时读到的偏误规范与提纲设计法；目的是降低友善偏见 / 社会期许偏差。

### 主问题模块（每个研究维度一个模块，按 brief 数量增减）

```
■ 模块 N：[模块主题 = 研究目标拆出的一个维度]
  研究目的：[这个模块要回答研究目标里的哪个问题]   ← 给执行者看，访谈时不直接念

  主问 N.1（O 客观/场景）：[还原事实与场景的开放问题]
    └ 追问：[请举例 / 还原最近一次 / 具体到某次]      （时机：回答不够具象时）
  主问 N.2（R 感受）：[对上面场景的感受、喜欢/不喜欢及依据]
    └ 追问：[哪一点让你这么觉得？]                    （时机：核心相关、值得深挖时）
  主问 N.3（I 理解/动机）：[感受背后的原因——还原场景→拆动机，不直问"为什么"]
    └ 追问：[换个场景是否也这样？对比另一选择？]      （时机：出现新发现/新角度时）
  主问 N.4（D 决定/期待）：[现有问题、改进期待、下一步打算]
    └ 追问：[如果……会怎样？理想中是什么样？]
```

模块写法约束：
- **不必每块强凑 O/R/I/D 四层**，但问题顺序遵循「先还原、后挖因、再谈期待」。
- 每个主问尽量配 **2–3 级追问**，并标注**时机**（核心相关 / 不够具象 / 新发现）与**方式**（举例 / 对比 / 还原最近一次）。
- 深访可在合适模块**预埋情绪引导问题**（挖爽点：超预期的瞬间；挖痛点：最不满的经历），具体话术依运行时读到的访谈正典。
- **模块取舍按用户类型/阶段定制**：例如新用户重触达与首用场景，资深用户重使用流程与体验评价；规划期偏探索、迭代期偏评估诊断。
- 凡某块基于 draft 正典、或因无贴合场景打法而通用兜底，**在该块末尾标一句**（如「⚠️ 本模块基于 draft 规范 / 无贴合场景打法，通用兜底」）。

### 收尾

```
【收尾】
- 总括性问题：[整体上最希望改进的一点 / 还有什么没问到的]
- 必要但敏感的问题放这里问（如收入），戒备最低
- 致谢 + 说明后续（是否回访、激励发放）
```

## 二、用法提示（附在提纲后，给执行访谈的人）

```
【用法提示】
- 追问时机：[本提纲里哪些点最值得追问，对应三个时机]
- 追问方式：[举例 / 对比 / 还原最近一次 / 鹦鹉学舌复述确认 / 沉默 10 秒 等，取自访谈正典]
- 本次要特别防的偏误：[结合 brief 点名 2–4 个，如锚定/友善偏见/社会期许，并给一句怎么防]
- 形式注意点：[深访/拦访/焦点小组 各自的执行提醒，取自对应正典]
```

## 四、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实 brief 重写）

> 下例是凭空编的格式演示，不是任何正典内容，也不针对真实项目。看完格式即弃。

```
■ 模块 2：首页信息流的使用体验
  研究目的：了解资深用户在首页信息流的真实使用流程与体验落差

  主问 2.1（O）：能不能讲讲您最近一次打开 App 首页，从看到信息流到点进某个内容，整个过程是怎么走的？
    └ 追问：当时具体刷到了什么？停在哪一屏？（不够具象时——请还原那一次）
  主问 2.2（R）：这个过程里，有哪一段让您觉得顺手、哪一段让您觉得别扭？
    └ 追问：是哪一点让您有这种感觉？（核心相关——深挖依据）
  主问 2.3（I）：您刚说"刷一会儿就退出来了"，那次退出前发生了什么、当时在想什么？
    └ 追问：换成在地铁上刷，会不会不一样？（新发现——用对比拆场景，而非直问为什么）
  主问 2.4（D）：如果这块能改一处让您更愿意停留，您最希望改哪？
  ⚠️ 本模块基于 draft 规范（interview-guide-design / orid 当前为 draft）。
```
> 注意上例如何把 ORID 落成具体问题、如何标追问时机与方式、如何就地标 draft——**形式照此，内容必须按真实研究目标和用户类型重新生成**。
