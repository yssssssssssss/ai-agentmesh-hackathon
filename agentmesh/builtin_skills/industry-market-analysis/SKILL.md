# Industry Market Analysis — 垂类行业市场分析工作流（频道改版决策支撑）

京东体验设计团队的通用工作流:设计师拿着它,能用一套固定的思考内核,把任意品类频道的行业问题想透——小到在对话里碰一个想法、拆一个竞品,大到产出一份能上会立项的完整报告。

**内核固定,外形随场景**(这条是本 skill 的第一原则):
- **锁死的是「怎么想」** —— 10 维框架、京东设计哲学做最高裁判、量化必有出处/绝不编数、落到设计师能开工的颗粒度。这些每次调用都不打折。
- **释放的是「产出长什么样」** —— 从"对话里直接给结论/对比表/灰阶线框",到一份 `.md` 底稿,到自包含可离线的 HTML 汇报页,按用户当下要什么伸缩,**不强制每次都产报告**。

**产出光谱(按调用成本从轻到重)**:

| 档 | 用户要什么 | 产出形式 |
|---|---|---|
| **第0档·对话态** | 碰想法、要个判断、拆一个竞品模块、看某点违反哪条设计原则 | 就在对话里给结论/对比/灰阶线框,不落文件 |
| **A·一次产出** | 快速摸底,先拿到能讲的结论 | 先产**一份 `.md`**(三档结论都给到);**产完主动告知"有编译好的、更好读的 HTML 汇报页(5 Tab、可离线),要不要出?"——用户说要才渲染,不默认硬出** |
| **B·分阶段精做** | 立项/年度规划/上会汇报 | 走完阶段后渲染 HTML 汇报页(5 Tab),内容底稿先用 `.md` 跑、自检通过再渲染 |

> **两条贯穿全档的定位(别忘)**:
> - **可被组合调用**:当我们作为"行业专家"和更专业的竞品分析/体验诊断 skill 拼一份**联合产出**时,进入**协作模式**——只贡献「行业洞察 + 品类差异资产」两块的**结构化内容**(`.md`/JSON 片段),**格式服从主编译方,不强推自己的 5 Tab HTML 骨架**(否则和别人的结构打架、破坏联合产出物)。5 Tab HTML 只在"我们独立出报告"时才是硬约束。
> - **产出不是终点,是讨论的起点**:任何一档产出后,都**主动提示用户"想深挖哪个点可以继续聊"**(如"分类页导购优化"想展开)——深挖就无缝转回第0档对话态,带着行业专家视角往下想,不是"出完就结束"。

## 北极星与边界（先理解，再动手）

- **自包含工作流,不重造也不外借。** 本 skill 的方法论正典(10 维度定义、三档深度标准、8 阶段执行法、京东设计哲学基线)全部随附在 `references/` 下,运行时**从本 skill 自己的 references 现读**,不依赖外部 wiki。你的工作是**读对的阶段文档、抽对的模板、用到这一个品类上**,而不是凭记忆默写"十大维度是哪十个"。
- **平台哲学是最高裁判。** 体验诊断问"违反哪条 6 原则",差异化定位问"站哪条价值观(自然/务实/包容/焕新)",设计推导问"继承还是增量"——每一步都回溯 `references/foundations/京东设计哲学(平台基线).md`。
- **量化必有出处,拿不到就标不编。** 每个 % / ¥ / 增速要么带引用,要么标"估算·待核实";AI 拿不到的数据(App 交互实况、内部 KPI、一手访谈)标【待补】并附"升档补数清单",**绝不编数**。**但硬数据(规模/增速/热度)不许直接标【待补】交差**——先穷尽京东站内一手数据(黄金眼/选品/指标),再抓公开权威源,都拿不到才标【待补】并注明已试哪些源。见 `references/foundations/权威数据取数清单.md`、`references/foundations/反幻觉六类硬规则.md`。
- **与 competitive-analysis 的分工:** 本 skill 覆盖"行业洞察→品类差异资产→竞品→体验诊断→设计策略"的**频道级全景**,竞品分析只是其中一个 Tab(走选样/四要素/心智象限的精简版)。若用户只想**深挖单一竞品的战略意图、敌我 SWOT、要不要跟**,那是 `competitive-analysis` 的活,不必起本工作流。

## 何时用 / 何时不用

**用**(无论轻重):
- 在对话里**碰一个想法**:"图书签到玩法从行业看有什么问题""这个入口该站哪条价值观"(→ 第0档,直接聊)
- **拆一个竞品**模块、要一张**对比表**或**灰阶线框**(→ 第0档)
- 某品类频道的**行业/市场分析**、赛道调研;频道改版前摸清赛道;频道年度规划;向决策层讲"凭什么这么改";从行业到设计策略端到端推导

**不用**:
- 和品类频道的行业/竞品/体验/设计**完全无关**的问题(纯技术实现、纯文案、跟设计无关的杂务)
- 已有成熟品类认知,只想借某个环节 → 直接取「阶段3 京东内诊」或「阶段6 设计语言推导」单跑,不必起全流程

> 注意:过去"单点优化、快速体检、查数据"被列为"不用",其实是**不该被逼着出一份重报告**——现在这些都走**第0档对话态**,照样用这套框架和设计哲学,只是产出留在对话里。别再把它们推出门外。

## 开始前:先读全貌

1. **必读** `references/workflow-overview.md` —— 10 维度 × 三档深度 × 8 阶段的一页纸全景。
2. **选档** `references/foundations/三档深度对照表.md` —— 轻/中/重,按场景选一档。
3. 建品类工作目录(如 `~/Desktop/宠物行业分析/`),把频道现状截图、竞品截图放进去。

## 三种用法(按调用成本从轻到重)

**第0档 · 对话态(最轻)** —— 用户只是碰想法、要个判断、拆一个竞品模块、问某点违反哪条设计原则。**直接在对话里回答**:该拆竞品就拆到模块级、该给对比就上四要素对比表、该给设计动作就配灰阶线框描述。**内核不打折**——照样锚定京东设计哲学、照样量化必有出处、拿不到的数据照样标 `【待补】` 绝不编数——只是产出留在对话里,不落文件、不起流程。见 `references/foundations/第0档-对话态怎么答.md`。

**用法 A · 一次产出(中)** —— 用户只给「品类 + 线上产品链接/依据」,用 `references/templates/报告模板-三档合一.md` 一次产出三档结论都给到的 `.md`。拿不到的数据标【待补】**绝不编数**,附「升档补数清单」。**产完 `.md` 主动问一句"要不要编译成更好读的 HTML 汇报页(5 Tab、可离线)?"——要才出,不默认硬渲染。**

**用法 B · 分阶段精做(重)** —— 按 `references/stages/` 里 1→8 顺序人机配合走完,产出单一档位精修报告,并在阶段8渲染成 HTML 汇报页。每份阶段文档自包含:目标 → 输入 → 动作 → 产出 → 自检。

> 三档可衔接:先在对话里(第0档)碰清楚方向 → 用 A 摸底 → 再用 B 对重点章节精做出报告。**从哪档起、要不要往上升,由用户当下的需求决定,不默认冲着出 HTML 走。** 产出后也可**反向回落**:用户对报告里某个点想深挖,就转回第0档继续聊,不是出完就结束。

## 8 阶段流程(用法 B)

| 阶段 | 文档 | 产出 |
|---|---|---|
| 1 澄清与档位 | `references/stages/阶段1-澄清与档位.md` | 锁定品类/档位/主聚焦/本地素材 → 运行计划 |
| 2 外部数据调研 | `references/stages/阶段2-外部数据调研.md` | A宏观 + C供给 + D竞品:市场规模、竞品、内容阵地 |
| 3 京东内部诊断 | `references/stages/阶段3-京东内部诊断.md` | E:频道现状、KPI、体验四类问题(挂钩 6 原则) |
| 4 交叉验证 | `references/stages/阶段4-交叉验证.md` | 剔除不可靠数据,标"待核实" |
| 5 机会与策略合成 | `references/stages/阶段5-机会与策略合成.md` | F:Gap 矩阵、机会打分、三档优先级 |
| 6 设计语言推导 | `references/stages/阶段6-设计语言推导.md` | G:品类属性→关键词→色板→组件 |
| 7 品类差异资产 | `references/stages/阶段7-品类差异资产.md` | 五段(心智锚点/视觉基因/文案语气/玩法基因/动效性格),每条带适配度+为什么+标杆+保鲜字段 |
| 8 报告装配与自检 | `references/stages/阶段8-报告装配与自检.md` | H+I 补齐,过自检 → HTML 汇报页(5 Tab) |

> 每份阶段文档自包含,按需打开对应那份,不必一次读完。

## HTML 汇报页 + 图表出图(阶段8 关键)

- **骨架统一、配色统一**(硬约束):页面结构/宽度/**5 Tab 归类**/**配色系统**全部固定——**报告页统一用一套清新配色**(白卡 `#ffffff` + 冷灰底 `#f5f6f9` + 蓝橙紫功能色,见阶段8「统一配色 token」),**不再按品类换配色**;**禁止改成长滚动页**;仅字体/母题图案允许按品类做轻微点缀。任何品类的报告都必须是同一套骨架 + 同一套配色,一眼可辨"同一工作流产出"。(注:阶段6 推导的品类色板是给**频道改版**用的**设计交付内容**,放进资产库 Tab 展示,与"报告页本身的配色"是两回事,别混。)
- **5 Tab 固定(顺序即优势叙事)**:行业洞察 / **品类差异资产** / 竞品分析 / 体验诊断 / 设计策略。**前两个 Tab(行业洞察 + 品类差异资产)是我们"垂类行业专家"的名片,前置着重展示**;后三个是针对京东现状的落地分析,可与更专业的竞品/诊断 skill 组合。品类差异资产 Tab 每份必带(阶段7 产出),不可省。
- **自包含单文件、离线可开**:CSS 内联,**不依赖外网 CDN**——换个没网的会议室也能打开。
- **出图**:给关键数据(机会打分、好评率、四类问题分布…)出**纯 SVG 单色图**嵌进报告;若用外部图表 skill(如 lieflat-chart),**只用纯 SVG 图型、禁用依赖 CDN 的图型**,否则破坏离线特性。详见 `references/stages/阶段8-报告装配与自检.md` 的「图表可视化建议」节。

## 核心原则(每步都守)

- **平台哲学是最高裁判**(6 原则诊断 / 4 价值观定位 / 继承·增量判设计)
- **量化必有出处**,拿不到标【待补】绝不编数;硬数据先穷尽站内一手源再标
- **一句话结论**:每大节末浓缩 1 句(带对比、可引用)
- **保留品类特色**:视觉方向来自品类属性推导,不硬套通用风格
- **产出形式随档位,不散落**:第0档留在对话里、不落文件;A/B 档只产 1 份最终交付,中间产物不散落

> 一张对外/新人的可视化「一页纸名片」见 `references/framework.html`(能产出什么 + 8 阶段怎么做 + 覆盖什么)。它是**展示物,不是执行依据**:执行看 `references/stages/`,全貌看 `references/workflow-overview.md`。
