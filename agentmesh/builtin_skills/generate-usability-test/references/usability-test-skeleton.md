## 一、可用性测试执行包骨架（五件套）

固定五件套：**任务场景 → 出声思考脚本 → 观察记录表 → 度量计划 → 招募甄别**。开头先用一两句交代本次的**测试阶段与方法搭配**（探索性/评估性/对比性，依第 1 步判定）。

### 1. 任务场景（每条核心流程一个任务，按 brief 增减）

```
■ 任务 N：[任务名 = 一条核心、高频的操作流程]
  应用场景：[给用户一段贴近真实的情境描述，让他有代入感]
  起点页面：[任务从哪开始]      终点页面：[到哪算完成 = 成功判据]
  任务指令（念给用户/给到用户的原话）：[只给目标，不写操作步骤或按钮名]
  预计时长：[ ]
  ⚠️ 标注：[若基于 draft / 无贴合场景通用兜底，在此标一句；否则删]
```

> 约束（依运行时读到的任务设计原则）：选最核心流程、符合常规操作、明确起止页面、不过于简单、**不提供线索与操作步骤**；多任务按常规操作流串联、不冲突。

### 2. 出声思考脚本（主持人逐字稿）

```
【开场】
- 自我介绍 + 测试目的（一两句）：[我们测的是产品/方案，不是测你，没有对错]
- 出声思考训练：[请你边操作边把心里想的、看到的、卡住的都说出来；可先用"如何泡一杯茶"小例子热身]
- 减负说明：[无对错、批评同样有价值、不会因负面意见受伤；过程保密 / 匿名]
- 录音录屏许可：[征得同意]

【逐任务引导】（每个任务一段）
- 任务 N 引导语：[念应用场景 + 任务目标；"现在开始，请边做边说"；开始计时]
- 过程中只做：[必要时提示"继续说出你的想法"；除此不打断、不指路、不评价]

【事后访谈】（全部任务做完后，按梯度追问，别只问"好不好"）
- 认知习惯层：[你平时是怎么完成这件事的？刚才哪一步和你预期不一样？]
- 需求关注层：[这个环节你最在意什么？刚才卡住的地方，当时在想什么？]
- 深挖"为什么"：[就某个具体卡点继续追问原因；高分也要逐环节追问细节]
- 收尾：[整体最想改的一点 / 还有什么没问到；致谢 + 激励发放]
```

> 减负说明、不打断、复现真实操作、事后三层追问的写法，依运行时读到的偏误规范与可用性测试 STEP5；目的是压制霍桑效应、友善偏见与峰终定律。

### 3. 观察记录表（给现场执行者即填）

```
| 任务 | 是否完成(到终点?) | 完成时间 | 出错/求助次数 | 关键事件 & 体验问题(卡在哪) | SEQ(单任务难易) | 观察备注(表情/迟疑/原话) |
|---|---|---|---|---|---|---|
| 任务1 | □完成 □部分 □失败 | __:__ | | | [   ]/[满分] | |
| 任务2 | □完成 □部分 □失败 | __:__ | | | [   ]/[满分] | |
| … | | | | | | |
```

> 字段对应运行时读到的「数据收集表」要素（是否完成 / 完成时间 / 关键事件体验问题 / 满意或难易度）；SEQ 点数以量表库为准，别写死。

### 4. 度量计划

```
- 任务成功率：[每个任务的成功判据 = 是否从起点页到达终点页；统计 完成/部分/失败 比例]
- 单任务难易 SEQ：[每个任务做完立刻问；点数与"低分追问原因"口径取自量表库；标注均值基准]
- 整体可用性 SUS：[全部任务后施测；题数·点数·换算口径取自量表库；解读对标基准/百分位，不看绝对分]
  （问卷要短可改 UMUX-Lite，并说明可换算回 SUS 基准）
- 其他度量（按目标可选）：[出错率 / 完成时间；竞品对比可引入评测分档或 GSB；视觉关注可引入眼动 AOI 指标]
- 样本量与依据：[Nielsen/基准样本量 + 未出席率上浮；定性以信息饱和判停、可分阶段招募]
- ⚠️ 标注：[凡现写量表 / 库未覆盖 / 基于 draft，在此标一句]
```

### 5. 招募甄别

```
- 关键特征 + 配额：
  | 关键差异维度 | 取值/分层 | 配额(人) |
  |---|---|---|
  | [如 使用频次] | [新/资深] | [ ] |
  | [如 角色(B端)] | [终端用户/决策者…] | [ ] |
  合计样本量：[N]（含未出席率上浮后实际招募 [N+] 人）

- 甄别问卷（题量克制）：
  · 关键行为/资格题：[必须满足的筛选条件] —— 配干扰项模糊筛选目的
  · 人口学/分层题：[与研究目标相适配的维度]
  · 开放题（评估表达力与配合度）：[一道与主题相关的开放问题]
  · 联系方式 + 参与意愿
  · [涉及眼动：追加视力等测试条件题]

- 复核与停止判据：[电话复核要点；信息饱和判停 / 分阶段先招 4–6 人再追加]
```

## 二、偏误与可用性自检结果模板（对照偏误规范逐条）

> **逐条对照运行时读到的 `methods/toolbox/collection/respondent-bias.md`**（并借 `usability-testing.md` STEP4 试点视角），一项一行。
> 条目与措辞**以现读为准**，下面是常扫的几类，按实际补全。

```
## 偏误与可用性自检结果（对照《受访者偏误规范》，规范 status: [draft/reviewed]）

| # | 检查项 | 结论 | 证据 / 定位 / 怎么改 |
|---|---|---|---|
| 1 | 任务表述只给目标、未泄露操作步骤/按钮名 | ✅/⚠️/❌ | [对应到哪个任务；不通过给修正] |
| 2 | 霍桑效应：用熟悉环境 + 引导复现平时真实操作，未诱导表演 | ✅/⚠️/❌ | […] |
| 3 | 友善偏见/峰终：不止问"好不好"，逐任务逐环节深挖、高分也追问 | ✅/⚠️/❌ | […] |
| 4 | 顺序/锚定：多任务或多方案已随机化 / counterbalance | ✅/⚠️/❌ | […] |
| 5 | 开场减负说明（无对错/保密匿名/不因差评受伤）+ 事后复述求证 | ✅/⚠️/❌ | […] |
| … | …（按现读规范补） | | |

自检结论：[共 N 项，✅ x / ⚠️ y / ❌ z。❌ 已回改至 0 项；保留的 ⚠️ 说明：…]
```

> 规则：有 ❌ 必须回第 3 步改脚本/任务再自检；保留的 ⚠️ 要逐条说明为何可接受。正典为 draft 时在此声明「基于未评审正典，定稿后需复核」。

## 四、形态示意（仅示范"长什么样"，**勿照抄内容**——务必按真实 brief 重写）

> 下例是凭空编的格式演示，不是任何正典内容、不是标准量表题干，也不针对真实项目。看完格式即弃。

```
本次为「灰度上线前 · 评估性可用性测试」，方法搭配：面对面任务测试 + 出声思考 + SUS。

■ 任务 1：报名一场大促活动
  应用场景：你关注的双 11 大促报名刚开始，你想让自家店铺参加。
  起点页面：商家后台首页    终点页面：提交报名素材成功页
  任务指令：请用这个后台，把你的店铺报名进这场双 11 大促活动。
  预计时长：约 5 分钟
  （注意：没有写"点营销中心 → 找大促 → 选商品"，只给目标——否则会错过用户找不到入口的真实卡点）

【开场·节选】我们今天测的是这套后台好不好用，不是测你，怎么操作都没有对错；
请你边操作边把心里想的说出来，比如"我以为报名在这里，但没找到"……全程录屏，可以吗？

观察记录（任务1）：□完成 ☑部分  用时 06:12  求助 1 次  卡点：在"营销中心"反复找入口
  SEQ：3 / 7（低于均值，已就卡点追问）  备注：皱眉、来回滚动两遍

度量：成功率按"是否到达提交成功页"判定；每任务后问 SEQ；全程结束施测 SUS、对标基准解读（不看绝对分）。
⚠️ 本包量表口径与样本量基于 draft 正典（usability-testing / standardized-ux-scales / sampling 当前为 draft）。
```

> 注意上例如何只给任务目标而不给操作步骤、如何用开场压制霍桑/友善偏见、如何把成功率落到起止页面、如何就地标 draft——**形式照此，内容必须按真实测试对象、阶段、用户重新生成**。
