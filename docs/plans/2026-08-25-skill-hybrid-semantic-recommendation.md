# Skill 混合语义推荐开发设计

## 状态

功能已实施并通过全量代码门禁和真实界面验收；84-Skill 量化质量与性能门槛仍待专项评测。

## 背景

AI 工作台已经通过 `POST /api/skills/matches` 为当前用户检索全部已接入、已启用且可见的 Skill，
并允许用户把推荐结果写回 Composer，以显式 `$skill-name <task>` 的方式执行。当前匹配器是确定性的
BM25/IDF 词法排序，使用中文二元切分和少量同义词；它无法稳定理解“用研 = 用户研究”等口语表达，
也会因为无意义的句首词稀释覆盖率而错误返回空结果。

项目同时已有以下基础设施：

- 可选的 Embedding Provider、SQLite 向量存储和内容哈希失效机制；
- OpenAI Agents SDK 模型选择和结构化输出；
- 服务端 Skill 可见性、启用状态、资源就绪度和绑定检查；
- 10 个受治理 Skill 的自动编排能力。

## 目标

1. 让自然语言、简称、中英文混合表达能稳定关联到合适的 Skill。
2. 对明确请求保持低延迟；仅在候选接近、请求模糊或词法证据不足时调用 LLM。
3. Embedding 或 LLM 不可用时可降级，推荐接口不因此返回 5xx。
4. 推荐结果可解释、可审计，并且绝不泄漏当前用户无权看到的 Skill。
5. 保持显式执行边界：推荐不会自动执行 Skill，也不会扩大自动编排或 Tool 权限。

## 非目标

- 不把 74 个新增 Skill 加入自动编排白名单。
- 不让 LLM 读取或执行完整 `SKILL.md` 指令、脚本及任意 metadata。
- 不引入新的向量数据库或独立检索服务；84 个 Skill 使用现有 SQLite 即可。
- 不根据推荐结果自动授予 Tool、MCP、文件或网络权限。

## 方案

```text
认证用户
  -> 过滤不可见、停用、资源不可用的 Skill
  -> 构造安全能力卡（名称、标题、公开描述、别名、阶段）
  -> BM25/FTS 召回 + 可选 Embedding 召回
  -> RRF 合并并截取最多 16 个强候选
  -> 置信度门控
       -> 单一明确需求：返回“首选 + 有意义的备选/互补项”，共 2 个
       -> 候选接近：LLM 对强候选结构化重排/澄清
       -> 词法与向量证据不足：LLM 对最多 100 张授权能力卡做语义召回
       -> 明确越域：返回空结果
  -> 服务端校验 LLM 返回 ID 属于授权候选集
  -> 多意图每个交付物选择 1 个、最多 5 个；点击后仍走显式 `$skill-name <task>`
```

### 能力卡和索引

`skill_definitions` 加入现有 FTS/向量索引。索引文本只能包含：

- Skill 名称、规范标题和公开描述；
- 用户或管理员配置的别名；
- `short-description` 与 `agentmesh-stage` 两个允许字段。

不索引 `instructions`、来源路径、作者、所有者或其他 metadata。向量以 `模型名:维度` 签名与索引文本
共同计算内容哈希；Skill 内容、Embedding 模型或维度变化时都会自动重建，旧向量不得继续参与排序。
传给 LLM 的公开描述优先取能力画像 `display_description`，其次取同步生成的 `short-description`，
最后才使用去除 `Boundary:` / `边界:` 后内容的原始描述，并统一截断到 140 字。74 个生成包在同步时均写入
不超过 100 字的 `short-description`；容易混淆的研究报告、截图分析、旅程图等能力使用人工校准摘要。

### 候选合并

- 词法排序保留精确命令、产品名和专业术语优势。
- Embedding 排序补足同义词、简称和跨中英文表达。
- 使用 Reciprocal Rank Fusion 合并排序，不直接比较 BM25 与余弦分数。
- 向量候选先通过 `0.4` 的最小余弦相似度门槛，避免 Provider 返回的完整排序被误当成有效召回。
- Embedding 默认关闭；关闭、超时或返回非法向量时记录降级诊断并继续词法路径。
- 查询 Embedding 的单次请求超时为 `0.35` 秒，整体 FTS/向量检索超时为 `0.45` 秒。
- 用户任务在词法、FTS、Embedding 和 LLM 之前统一进行凭据、联系方式和本地路径脱敏；JSON 中的敏感 header/key 也会先被结构化覆盖。
- 公开描述中 `Boundary:` / `边界:` 后的反例不进入词法、FTS 或 Embedding 索引；重启 reload 会重建旧投影。

Skill 定义与能力画像仍同步写入 SQLite FTS；Embedding 索引改为后台串行补齐。应用启动不等待待建
索引总量（当前全量重建为 84 条 Skill 定义和 21 条能力画像）；单条索引失败只会把该记录标记为
`FAILED`，不会中断后续记录。下次启动索引时会先把 `FAILED` 重置为 `PENDING` 后重试；worker 运行期间
收到的新扫描请求会记录为待重扫，并在退出前再扫描一次，避免遗漏并发写入。推荐接口始终保留词法降级路径。

### 条件式 LLM 重排

正常情况下 LLM 只接收合并后的最多 16 张安全能力卡。若没有任何可靠的词法或向量候选，则使用当前
用户已授权目录中的最多 100 张压缩能力卡做语义召回，避免 Embedding 默认关闭时退化成“只能重排关键词”。
以下任一条件触发模型判断：

- 没有通过确定性置信度门槛的候选；
- 前两名分差不足，无法可靠区分；
- 请求明确包含多个交付物，需要为每个交付物选择一个 Skill；只有候选工作流互斥且无法判断时才澄清。

单一明确需求默认推荐 2 个：第一项是最匹配的首选，第二项必须是能实质帮助同一结果的备选方案或互补
能力。若调用方显式传入 `limit=1`，则只返回首选；若授权目录中确实只有一个适用 Skill，也不拿无关能力
凑数。多意图仍按每个独立交付物选择 1 个，最多返回 5 个。

结构化返回仅允许包含候选 Skill ID、排序、是否无匹配和一个可选澄清问题。服务端在模型调用前剔除
用户明确否定的 Skill，并在模型返回后再次校验；同时丢弃候选集之外的任何 ID。模型失败、超时、输出非法或未配置时退回混合召回结果。推荐理由由服务端根据能力卡和命中
证据生成，不使用模型自由编造的解释。模型不得为了填满结果数量而加入无关能力，也不得把 Skill 执行阶段
才需要的输入误判为推荐阶段必须澄清的信息。若模型同时返回有效 Skill 与补充问题，服务端保留两者。
LLM 重排超时由 `AGENTMESH_SKILL_MATCH_LLM_TIMEOUT_SECONDS` 控制，默认 `8` 秒；SDK、Provider 与外层
deadline 的超时统一降级为 `llm_rerank_timeout`，不会返回 5xx。

### 权限与执行边界

权限过滤必须发生在 FTS、Embedding 和 LLM 之前；查询只能在当前用户已启用、可见且运行语料可用的
Skill ID 集合内进行。`execution_readiness=unavailable` 的 Skill 会被排除；`tool_limited` Skill 仍可推荐和
显式启动，但不会进入自动编排，也不会因此自动授予缺失工具。推荐完成后不产生执行副作用。用户点击
推荐项时仅填入显式命令；真正执行时继续重新校验 Skill binding、资源和 Tool Grant。

`SkillCandidateRetriever.eligible()` 及其 10 个自动编排 Skill 白名单保持不变。

## API 与界面

保留 `POST /api/skills/matches` 和现有请求结构，请求最多返回 5 项。响应增加向后兼容字段：

- `mode`: `lexical`、`hybrid`、`llm_reranked` 或 `fallback`；
- `clarification`: 无法唯一判断时给用户的简短问题，否则为 `null`；
- `diagnostics`: 仅包含稳定、非敏感的降级代码；
- 每个结果返回 `execution_readiness` 与 `missing_tools`，供界面区分完整执行与“工具待接通”。

界面对单一明确需求显示 2 个结果，对多意图显示最多 5 个结果。`tool_limited` 结果保留“使用此 Skill”入口并展示缺失工具；存在
`clarification` 时显示在结果之前；无匹配时区分“需要补充信息”与“当前没有合适 Skill”，避免把所有
空结果都描述成能力缺失。

## 失败与回退

- Embedding 未配置或失败：词法召回 + 条件式 LLM。
- LLM 未配置或失败：BM25/FTS + 可用 Embedding 的确定性排序。
- 两个 Provider 都不可用：保留改进后的词法匹配；含否定但无法安全判定的请求 fail-closed。
- 越域请求：返回空结果，不为了避免空态而强行推荐。
- 所有 Provider 错误均转成稳定诊断码，不把 URL、密钥或响应正文返回给客户端。

## 验收目标（量化门槛待专项评测）

- 清晰单意图 Top-1 准确率至少 85%，默认返回“首选 + 备选/互补项”共 2 个，Recall@2 至少 90%。
- 中文口语和同义表达 Recall@5 至少 95%。
- 越域误推荐率不超过 5%，越域拒绝率至少 90%。
- 未授权、停用或不可用 Skill 在召回、LLM 输入和最终响应中的泄漏数均为 0。
- 确定性路径 p95 不超过 500 ms；当前真实模型触发 LLM 时目标 p95 不超过 9 秒；Provider 失败不产生 5xx。
- 回归样例必须覆盖“我想做一个用研报告”“生成用户研究报告”“用户研究报告”、精确 Skill 名、
  多意图任务、无关任务和提示注入文本。
- 后端全量 pytest、Ruff、前端 Vitest、TypeScript 构建和真实桌面/移动端交互全部通过。

## 发布与回滚

复用现有 `AGENTMESH_EMBEDDING_*` 与模型配置，不新增密钥类型。Embedding 当前默认关闭；未配置时
系统仍可工作。代码回滚只恢复旧匹配器，不涉及用户数据迁移；新增索引可以安全重建。

最脆弱的假设是现有 Embedding Provider 能稳定理解中英文设计术语并保持可接受延迟。如果该假设不
成立，系统自动退回词法 + 条件式 LLM，API 和显式执行路径保持不变。
