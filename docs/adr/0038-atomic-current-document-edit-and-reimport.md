# ADR 0038：当前文档编辑与手动重导入的原子提交

状态：接受；补齐 ADR 0035 的手动编辑/重导入路径，仍不代表整个来源层或执行阶段完成。

手动导入原先逐条保存 staging 片段与进度，最后逐条激活；中断会留下部分数据。编辑则先提交新正文，再扫描全部个人记忆使旧片段失效；失效失败时正文已经变更。实际 API 故障测试分别复现了这两种不一致。

`DocumentMemoryStore` 复用 DocumentRecord、Source、个人 Memory、Audit 和现有 SQLite 索引，不新增持久工作流。手动导入在事务外对当前快照分块，正文最多 1 MiB，标题/文件名各 512 字符，片段最多 2,200 项。原生 URI 的 Document ID 最多 120 字符且不能含 `/` 或 `#`。写事务重新读取文档、owner、调用者和项目，检查双方当前 active 身份、workspace、项目状态及成员关系。保留已有管理员编辑/导入例外，但角色来自当前持久记录；界面仅提供本人当前项目资料。

正文、标题、原始 Source、元数据、owner/scope/version 等完整文档快照 hash 在 BEGIN IMMEDIATE 后重新比较；进度/updated_at 不属于导入输入，其他已完成的相同导入不会形成伪冲突。同一版本在等待写锁时被更换正文也会拒绝。公共 import-to-memory 接受可选 expected_version；旧调用省略时选择当前版本，新界面显式提交所选版本，不能静默换成更新的正文。

片段 ID 继续由 document/version/index 稳定派生；新增 Source 同样稳定，明确 owner/workspace/project 与 `document://id#vN/chunk_index`。所有 Source、当前片段、FTS、向量待处理状态、完整进度和导入审计一次提交。索引/数据库失败全部回滚，API 仅返回静态错误代码。并发与数据库重开不重复创建片段或审计；正常重复操作可以重建缺失的搜索投影。

已有片段须与当前原文、标题、owner/scope、类型及版本化来源一致。仅匹配的原生 active/staging 片段可以显式补齐；未知额外片段、来源冲突、改写/高敏/结构化/派生载荷、已归档或已遗忘记录要求检查，不能借重导入恢复。缺少稳定 Source 的匹配记录可补齐来源；不能冒造旧 ParseJob 的原始上传证明、claim 或完成结果。旧不完整 Job 的修复仍是独立问题。

PATCH 在同一写事务内验证 expected_version 和当前权限，保存新正文/版本，更新文档索引，并在 SQL 中使本人同 workspace/project 的旧原生摘要/片段失效。失效记录的 FTS/向量/状态同步删除，旧向量返回不能重新附着。其他人的独立记录和共享团队知识不改写。唯一自动协作摘要同事务保守撤回，后续发布只能使用合格的当前材料；这不宣称普通归档、全部外部 Source 或共享派生关系已完成通用失效传播。

当前片段查询在 SQL 中限定 owner/scope/version，最多 2,200 项，单条 JSON 最多 8,192 字符，再解码；不再扫描全部个人记忆。旧 `activate`/逐条进度/激活 helper 删除。新上传的 durable ParseJob 闭环沿用 ADR 0035，不为本次修改另建运行实体。

Knowledge 的“编辑与重新导入资料”复用现有资料查询，草稿保留已观察版本。保存正文与生成片段是两个明确操作，未保存的草稿禁止导入，冲突提示读取最新版本；未知网络结果要求检查当前版本/片段数。相关资料、记忆、学习及市场缓存失效。原上传记录注明“本次上传 vN”，不把历史成功解释成当前编辑版本已经有片段。事实确认和团队独立审核不自动完成。

25 项新专项覆盖导入与编辑故障回滚、Source/索引修复、额外旧片段、并发/重开、等待写锁期间身份/workspace/成员/项目/角色变化、同版本正文变化、版本选择、归档、遗忘/撤回与大小限制。此前相关组合在 Python 3.12/3.13 各 153 项通过；新增最后四项与正文/JSON 上限由后续专项与最终完整快照核验。前端 240 项/49 files、OpenAPI、生产构建与 bundle 检查通过。Ego Lite 在独立临时库、关闭全部 Provider 的条件下实际上传、编辑到 v2、显示 0/0、重新导入到 1/1、重复操作及刷新恢复；布局简化后再次通过可见按钮保存到 v3/0 个片段并重新导入到 1/1；最终截图已检查。最终结果与原始失败日志见 `docs/verification/2026-10-06-atomic-document-edit-and-reimport.json`。

首次完整回归两版均为 2,423 passed / 2 failed；两项失败是非超时 SDK 测试的 deadline 断言。单独运行原测试均通过。临时库记录的单个 Run 时间跨度超过 900 秒，而全轮 monotonic 用时为 775 秒，支持宿主 UTC 跳变这一解释。只在这两项非 deadline 测试使用从 captured UTC 以 monotonic 推进的测试时钟，统一 Runtime/Session/model handoff；生产 deadline 和专门的过期测试不更改。周边 SDK 专项两版各 83 项通过；最终完整重跑 Python 3.12/3.13 各 2,425 项通过、5 个既有 PyMuPDF 警告；不把首次失败快照称为通过。前端入口因原生折叠内容的可见性检查失败，简化为直接可见的资料选择区，再次 240 项通过、2.63 秒构建及实际截图检查通过。

本切片没有解析器进程隔离/硬取消、启用向量 Provider 的授权/容量证明、企业连接器水位、通用 Source 失效传播、全部 SDK 成本/交付治理或真实模型质量结果。阶段 3/4/5 的这些内容继续开发。
