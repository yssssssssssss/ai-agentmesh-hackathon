# 0058：增量来源同步、持久失败与同步界面

日期：2026-10-07。状态：手动连接器切片完成，完整优化方案仍在实施。

延续 ADR 0057 的一页一次读取和现有 SQLite 原子提交，扩展同一游标，不引入第二套任务系统。旧游标通过默认字段兼容；首次失败允许没有成功读取时间，避免把失败显示为已完成。

GitHub 使用固定 `since` 边界，整轮各页复用同一边界。完成最后一页才将水位推进到本轮开始时间，下一轮回退 60 秒重叠读取并按内容去重。首轮、显式完整复核或距离上次完整读取至少一天时执行完整扫描；本地目录始终完整扫描。一天规则仅在用户发起同步时生效，没有后台定时调度。参数依据 [GitHub Issues REST 文档](https://docs.github.com/en/rest/issues/issues?apiVersion=2026-03-10)。

完整扫描累计最多 1,000 个来源身份。最后一页才把本轮未见的旧活动来源标记为 unavailable，保留记录；本轮开始后重新观察的来源不因旧扫描遗漏失效。增量结果的缺席不表示删除。分页读取不是 Provider 一致性快照，遗漏也不能证明物理删除。

读取失败以静态错误代码、失败时间、次数和新游标版本持久化，并与审计共同提交。提交前重复实际用户、项目、配置和原游标检查。临时 Provider 故障保留最后观察；访问/目录不可用则在同一事务停止引用既有来源。403 可能表示限流，不能宣称已确认权限撤销。访问恢复后从第一页完整读取，避免直接续页遗漏已失效的前页来源；其他失败保留原分页边界。HTTP 错误后需重新读取状态获取新版本。

Knowledge 提供同步、继续、重试、完整复核及最后成功读取时间。同步镜像正文只读，显示当前版本，显式导入使用当前版本；普通本人资料仍可编辑。同步不自动确认事实、共享资料或更改 Task。

本轮只运行直接受影响的检查：37 个后端测试、4 个前端测试、类型构建和定向 Ruff。临时服务中，Ego Lite 完成六份合成文档的两页同步、只读展示及一份资料的显式导入。真实隔离读取同步三份仓库资料和九个公开 Issue；后续零变化增量读取保持文档版本并推进水位。浏览器使用临时服务生成的测试身份，未修改真实登录状态或业务数据库。证据见 `docs/verification/2026-10-07-incremental-source-sync.json`。
