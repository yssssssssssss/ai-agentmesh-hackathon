# ADR 0050：直接 SDK 执行的状态提交与旧 writer 隔离

状态：接受（本地直接 SDK 状态提交切片）。本文覆盖直接聊天和直接工具审批恢复；完整预算、持久 Session/Runner 交付及规划 writer 管理继续实施。

ADR 0048/0049 分别加强普通合成封存和终态投影，但直接 SDK Run 仍有独立状态提交路径。受控真实 SDK 测试复现：Session 拒绝旧 writer 后，错误或取消处理重新读取当前 Run，将新 writer 标记为失败或取消；模型返回后的撤权/超时仍可提交成功；暂停快照生成后发生 writer 或 Session 变化，仍会保存旧审批。

复用已有 SQLite 写事务与执行身份摘要。`save_agent_run_with_event` 比较当前执行身份、writer generation、契约/定义版本、Plan 关联和 Runner。更新目标本身也不能转移 writer。重试规划的合法 Plan 关联变更显式携带关联前的 Run；普通旧执行不能用新读取对象替换自己的身份。没有增加运行状态机、外部存储或公开 API 字段。

直接完成在同一事务内复查当前 Session、主体、项目/成员、线程和期限，复用 Session 来源检查。暂停携带原执行 Run 和已有 Session checkpoint，提交事务重新核对当前资格、Session 版本/内容/来源及 checkpoint，再一起保存 Run、事件和收件箱。旧 writer 冲突不改变当前执行，也不留下新审批条目。

直接聊天与审批恢复将完成/暂停纳入异常处理；同一 writer 的提交拒绝收敛为失败，使用静态错误码，恢复失败清除旧暂停状态。失败及取消使用原执行身份，非读取工具结果未知仍保留 `external_outcome_unknown`，不自动重试副作用。审批恢复的内部取消给树取消操作传入预期身份；用户主动取消仍作用于当前 Run。

终态 Run、收件箱关闭和事件复用同一事务。失败不会留下可操作的旧审批；事件失败整体回滚，原 Run 和收件箱保持原状，重试可提交一次。并发完成只有一个终态事件。这里不撤回已经合法提交到 Session 的先前内容，也不将当前权限检查冒充完整生成输入或外部原文证明。

新增 **36** 项场景覆盖直接/恢复成功、模型与提交窗口的 writer 替换、晚取消、主体/项目/成员/线程撤权、期限、审批 Session/checkpoint 变化、终态收件箱收敛、事件故障回滚与并发提交。聚焦验收 **36 passed / 75.39 秒**；最终 Python 3.12/3.13 的 **57** 组关联回归各 **932 passed / 无警告**，耗时 **408.45/407.78 秒**。Ruff 与 diff 检查通过；精确记录、开发阶段未通过结果及当前文件摘要记录在 `docs/verification/2026-10-07-fenced-direct-sdk-state-transitions.json`。公开 API/schema 和前端不变，未执行全后端、浏览器或真实模型/企业连接器验收。

本项不引入持久执行 lease，不证明远程模型实际收到数据，也不完成独立 producer 取消语义、全部规划异常/节点取消的 writer 管理、通用 Source 生命周期或完整输入失效传播。统一上下文、累计请求/成本预算、过程复用、连接器水位、部署级解析权限和真实模型/企业试点继续按主方案实施，阶段 3–5 保持实施中。
