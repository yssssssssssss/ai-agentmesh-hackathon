# ADR 0040：记忆绑定的当前授权、服务端身份与查询约束

状态：接受（绑定配置及普通查询约束；scout 材料资格与完整 SDK 治理继续开发）。

后续补充：跨消费者的内容类型含义与旧绑定确认规则由 ADR 0044 统一；本记录保留当时的类型筛选实现与验收快照。

原绑定 PUT 接受调用者指定的记录 ID。本人 Agent 尚无绑定时，提交另一 Agent 的绑定 ID 会通过 upsert 覆盖对方配置。GET 只要求登录，能读取他人的私人项目列表；PUT/DELETE 在写事务外使用登录时的用户快照检查权限。普通 `search_for_agent` 还会用绑定的第一个项目替换调用者指定的项目，并在结果数量限制后才筛选类型。

现有三个 HTTP 接口委托给 `AgentMemoryBindingService`，不新增持久实体或配置副本。GET 在一个只读快照中读取当前 User、Agent、权限规则与绑定。PUT/DELETE 先取得 `BEGIN IMMEDIATE` 写事务，再进行同样的授权；等待锁期间的停用、转移、工作区变化和权限撤销均在提交前生效。

只允许当前活跃、身份一致的用户管理同工作区 Agent：私人 Agent 由所有者或管理员管理，公共 Agent 使用现有 `manage_public_agent` 规则。管理员同样不能跨工作区读取或写入绑定。不可用 Agent/项目返回 404，无管理权限返回 403。配置读取不向无权限用户暴露私人项目 ID。

新绑定 ID 与时间由服务端生成，Agent 身份来自路径；请求中的 id/agent_id/created_at/updated_at 不控制存储身份。修改保留原 ID 和创建时间，只更新四个配置字段与服务端更新时间。新建使用 INSERT，更新和删除指向已验证的记录；两个同时创建的请求经数据库写锁串行化，保留一个绑定身份。指定项目必须当前活跃、同工作区且调用者可访问；私人 Agent 所有者也必须具备项目成员资格。空成员列表沿用现有开放项目规则。

配置载荷限制为 1–4 个 scope、最多 32 个类型（每项 1–80 字符）、最多 100 个项目 ID（每项 1–120 字符）和 1–100 个结果。非法输入返回 422。绑定只是收窄普通记忆授权，删除绑定也不授予其他用户/项目记忆访问权。

API 与内部绑定读取复用同一数据库检查：按 Agent 选择最多两条记录，存在多条、载荷无效或载荷 ID 与存储键不同则明确失败；API 返回 409，内部查询抛出既有 `MemoryContextConflict`。不挑选更宽松的一条，也不自动删除异常配置。旧异常记录的修复需另行处理。

普通 Agent 查询保留调用者指定的项目；项目未被绑定允许时返回空结果。类型白名单下推到现有搜索 SQL，在候选/结果预算之前生效，避免不允许的高排名结果挤掉允许的记忆。缺省绑定继续使用已有 scope/owner/project/lifecycle 授权。

绑定写入沿用 ADR 0039 的源事务失效触发器：创建/修改/删除可撤回依赖它的已发布摘要及索引；清理失败时绑定与摘要一起回滚。普通已授权 GET 不修改绑定或撤回当前摘要。并发测试在真实 SQLite 写锁等待处撤权，使用明确事件控制，不依赖 sleep 或真实 Provider。
