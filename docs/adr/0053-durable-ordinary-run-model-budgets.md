# ADR 0053：普通 Run 的持久累计模型预算

状态：本地确定性关联验收完成。完整累计成本、工具和远程预算尚未完成。

真实 SDK 受控复现了普通 Run 限制一次模型调用后，审批恢复仍调用第二次模型，以及 Session 压缩不计入相同 Run 的问题。此前普通执行只有逐请求检查，DeepSearch 的持久计量具有独立恢复和资源规则，不能直接将其用于普通 Run。

增加一个有界的 `run_model_budgets` SQLite 账本，归属于原 Run，不改变 Run/Plan 状态权威或公开模型。默认累计上限为 32 次调用、256,000 accounted tokens、65,536 输出 tokens，相同完整请求最多三次尝试；策略由首次预留冻结，后续审批、新 guard 或配置变化不重置。上限可通过 `.env.example` 中四项变量调整，无效配置明确拒绝。默认范围及上限都是策略，不是已验证的 Provider 上限或真实费用。

`RequestBudgetModel` 继续负责完整请求、隐藏状态及实际来源/Session 准入；取得原模型容量后重新检查完整请求，再以原执行身份在短 SQLite 写事务内预留 input 的 UTF-8 保守估计和已施加的 output cap。预留成功后才提交 Memory 使用回执。若后续准入在调用模型适配器前明确拒绝，调用方可释放自己未发送的预留；进入适配器后的错误、超时和取消保留额度，不退款。进程中断留下的预留保留，不凭重开或 TTL 退款。新增代码按领域聚合在 budget 模块，Store 只委托事务入口，未创建新网络服务或第二套运行状态。

已报告、非负且总量与 input/output 一致的正用量按实际 tokens 结算；缺失、畸形和 SDK 默认零值标记 unknown 并保留全部预留。普通请求显式要求 usage 和原始 usage。实际用量超过请求上限时先保存真实用量再拒绝结果；不把超过预估的已发生消费截断或改成零。已结算回执严格幂等，未知回执可接受后来可信的实际用量。账本和安全元数据事件一起提交；不存提示词、正文、工具参数、凭据或 Provider 错误正文。晚到回执只改变原预留，不写入后来替换的 Run writer。

本地规划、节点、审批恢复、合成和直接 Session 压缩共用账本；SDK 层每次实际模型适配器调用各自预留，原模型工厂默认关闭内部 HTTP 重试。现有显式 SDK 重试继续受原次数规则与账本约束。相同请求尝试检查使用完整已施加设置、转换后消息、工具/schema 的瞬时 SHA-256，不改动既有 Memory/Source canonical hash。预算失败保留已合法完成节点；没有可用结果时，普通 finalizer 保留预算原因而非仅报告输出契约失败。

测试使用真实 SDK、公开 Runtime 启动/恢复、MemoryContextService 与实际临时 SQLite。新增 **25** 项专项 **25 passed / 16.05 秒**；最终 Python 3.12/3.13 的 **67** 组关联回归各 **1,096 passed**，耗时 **560.11/558.97 秒**，无警告；Ruff 与 diff 通过。精确结果、开发阶段未通过记录和当前文件摘要见 `docs/verification/2026-10-07-durable-ordinary-run-model-budgets.json`。已验证审批和压缩累计、流式/非流式已知与未知 usage、重复请求、两节点和原子流重试、并发预留、数据库重开、回执重放、当前 writer/期限、原子事件失败回滚、容量等待/撤权，以及预算拒绝不提交 Memory 回执。初期样本遗漏历史消息持久化、Plan 创建模式和 Memory layer，修正 fixture 后另行复现；这些 fixture 失败不作为功能 RED。关联检查发现晚变更工具 schema 的错误优先级回归，已恢复先执行完整请求检查，不能以先前失败结果声称最终验收。

本项不提供价格映射、货币或费用限制，不合并自动巡检/工具/后台学习预算，不证明远程 Runner 的实际模型调用和交付，也不补齐规划 lease、完整审批到期恢复、持久输入失效或真实模型/企业质量。DeepSearch 保持原账本。API/schema 与前端不变，未执行浏览器、真实 Provider/企业连接器或全后端验收。阶段 3–5 仍实施中。
