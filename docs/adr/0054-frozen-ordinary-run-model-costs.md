# ADR 0054：普通 Run 的冻结价格与费用估算上限

状态：本地确定性关联验收完成。工具、自动巡检和远程费用预算仍未统一。

ADR 0053 已提供普通本地 Run 的累计调用与 token 账本，但不能据此显示真实金额或执行费用门禁。增加一个小型价格配置模型，复用原账本和写事务，不创建第二套预算状态或新服务。价格表按实际 SDK model name 精确匹配，由服务端声明货币、价格版本、输入/输出费率及可选有效时间；整个价格表与策略在首次预留冻结。既有无价格账本继续无价格，不因配置更新而补算历史费用。

`AGENTMESH_RUN_MODEL_PRICES_JSON` 接受至多 64 个模型、64 KiB 的严格 JSON 映射，重复键、非整数/负数费率、额外字段和不合法时间区间拒绝准入。费率单位是每百万 tokens 对应的货币百万分之一；例如输入费率 `1000000` 表示每百万输入 tokens 为 1 个货币单位。每次请求按整数计算并向上取整到货币百万分之一；不做汇率转换。货币代码和费率由运营配置，不宣称已验证 Provider 当前价格，不自动下载价格。

同时配置 `AGENTMESH_RUN_MODEL_COST_CURRENCY` 和 `AGENTMESH_RUN_MODEL_MAX_COST_MICROS` 才启用费用门禁；`1000000` micro 等于 1 个声明货币单位。缺少价格、价格到期/尚未生效或货币不匹配时，在实际模型适配器调用前拒绝；容量等待不会提前冻结或预留额度，取得容量后按当时有效价格准入。禁用费用门禁时，无价格请求仍可运行，但费用字段保持未知；跨货币请求不相加为一个金额。普通调用/token/output 上限仍独立生效。

已报告的一致正 usage 按冻结费率估算。未报告、失败和取消保留原 input 估计与 output cap 对应的费用预留，`reported_estimated_cost_micros` 保持未知；价格表不弥补 usage 缺失。只有适配器调用前明确准入拒绝能释放本次预留，释放后价格策略仍冻结。实际超限用量先按实记录，再拒绝结果；迟到回执沿用原价格，价格后来到期只拒绝新请求。并发预留、数据库重开、幂等回执与安全事件继续复用原事务规则。

公开 Runtime 的受控 SDK 场景复现了价格失败被普通 finalizer 改为 `output_contract_unsatisfied`，以及直接运行/审批恢复只保存 `RunModelBudgetError` 类名的问题。终态处理现在传递已有静态 `ModelAdmissionError.code`；不记录 Provider 错误正文。费用事件仅增加货币、估算/已报告用量估算、缺价/未知用量计数和价格版本，没有提示词、文档、工具参数或凭据。

新增 **41** 项确定性场景，专项 **41 passed / 33.02 秒**。最终 Python 3.12/3.13 的 **68** 组关联回归各 **1,137 passed**，耗时 **676.81/673.15 秒**，无警告；Ruff 与 diff 通过，测试启动后的 86 项执行源码摘要未变化。覆盖流式/非流式结算、配置变化、缺价/货币/有效期/畸形配置、累计并发费用拒绝、未知消费、未发送释放、真实超限保留、重开与晚到回执、审批恢复以及失败原因。精确结果、开发阶段失败记录及当前文件摘要封存在 `docs/verification/2026-10-07-frozen-ordinary-run-model-costs.json`。首次 Plan fixture 试图修改已创建 Run 的模式，修正创建方式后另行复现真实错误原因丢失；该 fixture 失败不算功能 RED。开发中给未定价旧预留增加时间戳改变了原接口值，以及空调用上限被忽略的问题均已修复；不以中间失败记录宣称最终通过。

这些金额是声明价格和 token 用量下的估算，不是 Provider 账单。未处理缓存优惠、批量折扣、税费、工具收费或后台学习费用，也未合并 DeepSearch/自动巡检/远程 Runner 账本。公开 HTTP schema 和前端不变；没有浏览器、真实 Provider、企业连接器或全后端验收。统一上下文、过程复用、持久规划/审批恢复、Source/Memory 失效与真实质量继续实施，阶段 3–5 尚未完成。
