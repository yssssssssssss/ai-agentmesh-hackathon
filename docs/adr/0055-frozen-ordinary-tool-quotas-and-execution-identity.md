# ADR 0055：普通工具的冻结额度与原执行身份

状态：本地确定性关联验收完成。工具费用、远程及后台统一计量尚未完成。

真实 SDK 复现了环境配置不能收紧既有 24 次工具上限、旧 Run 保存可归零计数，以及模型返回或容量等待期间更换 writer／Plan／节点尝试后仍调用工具的问题。普通工具复用 ADR 0053/0054 的冻结 Run 策略，保留现有 `Run.tool_call_count` 为唯一工具次数权威，不新增工具预算表或第二个计数器。

`AGENTMESH_RUN_MAX_TOOL_CALLS` 默认 24，仅允许整数 1–24。普通 SDK 首次模型预留冻结此值；只使用旧 Store 工具入口时，在首次工具准入冻结同一策略。后续配置变化、数据库重开和审批恢复不重新读取额度，旧调用方的 `limit` 参数只能进一步收紧。SDK 工具 hook 在实际工具开始前，用短 SQLite 写事务校验原 Run 摘要、作用域、Plan 定义与运行节点尝试，再同时提交计数、冻结策略和安全元数据事件。旧 Run 保存只能保留或增加既有计数；事务失败不留下部分计量。

工具额度表示已准入的 SDK 尝试，不是已发生的 Provider 消费或账单。进入容量队列后拒绝实际调用仍保留该次额度，不凭异常、等待或重开退款。原 Run 的模型、费用策略和工具上限一起冻结，但模型预留／用量回执保持原规则。DeepSearch 继续使用其既有独立计量，不套用普通工具账本。

Runtime 从原执行 Run/Plan 创建可序列化摘要；审批恢复先验证既有不透明 SDK checkpoint 和审批身份，再核对或补齐兼容字段。原生工具、Skill 资源与 governed MCP 在等待容量后、实际 claim 的同一事务内再次校验 Run/Plan/node 及两种期限。过期调用不能 claim、读取资源或发送给 MCP Provider；更换执行不能被旧调用接管。仍沿用既有 actor、项目和工具 grant 检查，不宣称完整 Tool-definition/grant 版本已经与 claim 原子绑定。

验证还复现了两个错误收敛问题。节点 attempt 已推进时，旧节点结果转换失败现在使用已有 `PlanExecutionConflict`，不再终止父 Run 的新执行。MCP SDK 默认将调用异常变为工具文本，使准入拒绝被后续 Session 错误覆盖；governed MCP 显式关闭该转换，调用异常停止执行，Runtime 只从 SDK 类型异常的直接原因恢复自有静态准入错误。不会解析 Provider 错误文本，也不会把未知外部写入变成可由模型自动重试的材料。

测试通过公开 Runtime 启动／审批恢复、Store 计量与 governed MCP 调用边界，使用真实固定版本 SDK、临时 SQLite 和受控模型／MCP，均不调用真实外部服务。新增 **23** 项场景，6 组工具关联回归 **103 passed / 62.34 秒**；最终 Python 3.12/3.13 的 **73** 组关联回归各 **1,189 passed**，耗时 **636.87/639.62 秒**，无警告。验收期间 300 项执行源码与依赖文件摘要未变化。精确结果、开发 RED、fixture 修正及源码摘要见 `docs/verification/2026-10-07-frozen-ordinary-tool-quotas.json`。初期 MCP fixture 给实例附加未使用的 approval 字段，实际仍停在审批门禁；改用公开审批恢复后才复现功能问题，原超时不计作功能 RED。DeepSearch 测试适配私有 lineage helper 的名称变化，保持其原有字段断言。

补充巡检回归发现已有审核变更测试混用固定日程时钟与真实命令时钟，跨日后合法触发 cron 补跑，而非期望的 change 触发。该用例统一固定审核时钟，删除额外篡改回执时间的步骤；原失败保留，不作为工具预算功能 RED。修正后 Python 3.13 的 6 组巡检／调度补充回归 **107 passed / 16.01 秒**，这组测试摘要在最终补充验收期间未变化。Ruff 与 diff 检查通过。

本项没有实现工具费用、所有后台／巡检预算统一、远程实际调用回执、MCP 调用 ID 全面恢复幂等、跨进程执行 lease、持久完整输入和来源失效证明。完整上下文组装、过程复用、连接器和真实模型／企业质量仍按主方案实施。公开 HTTP schema、前端与部署不变，阶段 3–5 保持未完成。
