# ADR 0052：冻结节点执行身份与审批恢复隔离

状态：本地确定性验收完成。对应主方案 10.3 的审批恢复、旧执行隔离与节点结果复用；不提供跨进程执行 lease。

真实 SDK 受控复现了节点审批恢复的旧执行接管：错误和取消处理重新读取 Run，终止替换后的 writer；正常结果和审批中断也能提交到新的执行。SDK 状态恢复期间替换 Run 后，原审批还会领取新执行。另一个窗口发生在节点已经合法提交、Runtime 重新读取 Run 后继续合成时。

沿用原 SQLite 事务、DAG、SDK RunState 与状态枚举。Runtime 和 executor 将原始 Run 与 Plan 传给领取、节点结果、暂停、审批恢复及内部取消事务；实际写入前核对 Run generation、契约/定义和 Plan 执行输入。恢复领取同时核对原暂停状态；显式用户取消仍针对当前执行。

服务端/直接执行保留严格 Runner 身份比较。现有 Runner 节点模式中，父 Run 的 `runner_id` 是最近领取节点的设备标记，可以随不同节点更新；DAG 控制面身份不以这个标记作为 writer。节点设备仍由原节点租约验证，终态提交保留当前设备标记。确定性检查覆盖同一/不同设备的节点交付，并验证 Runner 模式下 generation 或 Plan 输入变化仍拒绝旧节点结果；这不补齐远程节点租约的全部 generation/输入证明。

Plan 执行摘要包含目标、路由、候选、输入/输出契约、顺序、已批准来源身份及节点定义。节点摘要排除状态、尝试、错误和时间，状态与尝试沿用已有 CAS 单独检查。正常节点进展、重试与兄弟任务更新不改变执行定义；目标、输入绑定等变化会拒绝旧执行。摘要只在本次调用中比较，不改变已有 Memory/Source canonical hash 或持久载荷，也不新增第二套状态表。

executor 在首次领取、恢复及后续循环维持原身份，等待容量的节点在真正领取时复查；返回审批中断前也核对冻结的 Plan 和原尝试。已提交的节点结果保留，后续恢复接收原 Run/Plan，由 executor 检查后再加载合法最新节点状态，不接管后来替换的 writer。冲突收敛只能失败仍属于该执行的节点。普通错误路径发现未结算的外部写入时保留 `external_outcome_unknown`；不自动重试副作用。

测试通过真实 SDK、公开 Runtime 启动/恢复、公开 executor 和实际临时 SQLite 运行。受控 SDK 反序列化包装与数据库提交边界包装复现读写之间的变化，调用原 SDK/事务，不替换其业务结果。没有调用真实 Provider、OAuth、O2 或外部写工具。

新增 **54** 项场景：新节点身份文件 53 项，既有 Runner 路由测试补一项不同设备交付。初期七组聚焦回归 **169 passed / 225.97 秒**；修正终态节点后的四组 **131 passed / 113.29 秒**，修正 Runner 设备标记后的四组 **77 passed / 93.82 秒**。这些记录不替代最终来源验收。最终 Python 3.12/3.13 的 **60** 组关联回归各 **1,011 passed**，耗时 **529.70/530.18 秒**，无警告；Ruff 与 diff 通过。精确结果、两处兼容性回归、fixture 修正和当前文件摘要见 `docs/verification/2026-10-07-frozen-node-execution-and-approval-identity.json`。公开 HTTP API/schema 与前端不变，未执行全后端或浏览器验收。Runner 测试通过受控 ASGI 路由提交节点结果，不证明真实设备的模型输入交付。

范围限于本地已批准 DAG 的领取、节点提交、暂停、恢复与错误/取消收敛。完整规划/审批到执行的持久 lease、自动重启 replay、来源与生成输出的完整失效传播、累计请求/输出/成本预算、远程实际交付以及真实模型/企业质量验收继续实施；阶段 3–5 仍未整体完成。
