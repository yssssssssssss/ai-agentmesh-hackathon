# AgentMesh 10 分钟黑客松路演（场景闭环版）

> 这版不是按“六大模块”平铺功能，而是按“一次真实工作如何变成团队资产”来讲。适合 10 分钟现场路演，也适合后续改 PPT。
> 配套旧稿：[AgentMesh 10 分钟黑客松项目介绍 PPT 版](./AgentMesh-10分钟黑客松项目介绍-PPT版.md)

## 一句话定位

AgentMesh 把个人 AI 助手升级成团队数字员工网络：用户从一个聊天入口发起工作，后台由一组 Agent 接力完成资料、数据、风险和记忆沉淀，最后把一次工作变成可复用、可审计、可互助的团队资产。

## 这版讲法的核心变化

旧版是“模块介绍”：真实痛点、整体架构、个人能力、记忆模块、Agent 互助、项目价值。

新版是“场景闭环”：一个新人接手 618 家电会场，从找历史经验、查数据、看风险，到产出方案、沉淀记忆，再到另一个人的 Agent 主动复用这份经验。

这样讲有三个好处：

1. 评委不用先理解系统全貌，也能跟着一个具体任务往下走。
2. 三个最强能力自然串起来：个人能力拓展、三级记忆、Agent 互助。
3. 架构不再抢开场，而是在 Demo 后解释“为什么能做到”。

## 第 5 页：Demo 一，个人能力拓展，1:50 到 3:30

### 场景问题

新人问：

“去年 618 家电会场有什么复盘经验？入口点击率怎么样？这批外部素材有没有授权风险？”

### 解决方案

AgentMesh 不让一个 Agent 什么都干，而是让不同 Agent 接力：

- Research Agent 找资料。
- Data Agent 查指标。
- Risk Agent 审风险。
- Personal Agent 汇总答案并保留来源。

### 项目演示

建议现场演 2 到 3 步，不要全演太久。

1. 在 Workspace 输入 “$system.info”，展示当前可用技能和模型配置。
2. 输入 “$research.request 查找去年 618 家电会场的复盘经验”，展示带来源回答。
3. 输入 “$data.query 查询 618 会场入口点击率”，展示 Data Agent 证据。
4. 输入 “$risk.review 检查这批外部素材授权风险”，展示风险项进入 Inbox 或待处理区。

如果演示环境没有真实 Provider，就直接说：

“当前演示环境没有内网凭证，所以 research 和 data 会走 mock 或 local_metrics fallback。接口边界、权限、来源、审计和 fallback 是真实代码，不假装已经连上生产数据。”

“这一段不是在演示聊天机器人，而是在演示一次真实工作如何被拆成可审计的工作流。调研、数据、风险分别由不同 Agent 处理，最后由 Personal Agent 汇总。更关键的是，答案带来源，高风险项不会被 AI 自己处理，会进入人工确认。”

## 第 6 页：Demo 二，记忆沉淀，3:30 到 5:40

### 场景问题

AI 帮新人完成了工作，但如果结果只停留在聊天窗口里，下一次团队还是要重新问、重新找、重新判断。

### 解决方案

AgentMesh 把工作结果沉淀成三级记忆：

| 层级 | 作用 | 例子 |
|---|---|---|
| 个人记忆 | 保留个人工作上下文 | 今天查了什么、做了什么判断 |
| 项目记忆 | 沉淀项目阶段经验 | 618 会场入口策略、阶段复盘 |
| 团队记忆 | 审核后的可复用资产 | 大促会场首屏效率优先原则 |

核心不是“都存起来”，而是四件事：

- 分层：短期、中期、长期。
- 治理：候选记忆要审核。
- 检索：FTS5 + vector + RRF。
- 提炼：重复成功工作流变成 LearnedSkill。

### 项目演示

建议演三步：

1. 打开 Knowledge 我的知识，接受一条团队候选记忆。
2. 打开 Insights 工作洞察，看 short_term、mid_term、long_term 统计。
3. 讲 Skill 提炼：同类成功工作流达到阈值后，skill_extractor.py 会提出 LearnedSkill 草稿。

如果 Insights 中某些卡片还是参考数据，要说清楚：

“这个卡片的展示数据是参考数据，但背后的 Skill 提炼逻辑和测试在代码里已经存在。我们不把没接线的前端演成生产能力。”

“这页是项目里最有技术厚度的部分。我们不是把所有内容塞进知识库，而是把工作内容变成有层级、有权限、有状态的资产。个人记忆帮助自己继续工作，项目记忆帮助项目复盘，团队记忆必须经过审核，才会变成大家都能复用的知识。”

## 第 7 页：Demo 三，Agent 互助市场，5:40 到 7:20

### 场景问题

团队知识如果只能靠人主动搜索，价值还是有限。一个人正在做的问题，可能另一个人的 Agent 已经有经验，系统应该主动发现谁能帮谁。

### 解决方案

Agent 互助市场做三件事：

1. Agent-1 自动发布“我最近需要什么帮助”的信号。
2. Agent-2 扫描市场，发现自己有相关经验，就发起匹配和代答。
3. 用户采纳后，系统记录 ContributionPoint，并写回记忆血缘。

### 项目演示

建议演四步：

1. 打开 Collaboration 页面，看市场参与者、供需信号、完成匹配、授权记录。
2. 展示加入市场 / 退出市场的 opt-in 开关。
3. 打开 Market 页面，看当前用户个人视角：我的求助、收到的回答、给出的回应。
4. 展示一条提前触发好的真实匹配。演示前用 publish_all_signals(store) 和 scout_all(store) 触发，不要现场等 worker 周期。

### 技术架构

~~~mermaid
sequenceDiagram

  participant A as 用户 A 的 Agent
  participant B as Blackboard / Market
  participant C as 用户 B 的 Agent
  participant G as Consent / Risk Gate
  participant M as Memory
  participant P as ContributionPoint

  A->>B: publish_all_signals 发布 marketplace_signal
  C->>B: scout_all 扫描信号

  end

~~~

### 口播内容

“这一步展示的是从静态知识库到主动协作网络的变化。用户 opt-in 后，个人 Agent 才参与市场。系统发布的是需求信号和抽象答案，不是把原始记忆直接暴露给别人。被采纳的帮助会记录贡献点，这为后续排行榜和激励规则打基础。”

## 第 9 页：为什么这不是套壳 ChatBot，8:20 到 8:55

### 演示内容

对比表：

| 维度 | 通用 ChatBot | 企业知识库 | AgentMesh |
|---|---|---|---|
| 入口 | 对话 | 搜索框 | 对话 + 显式 skill |
| 能力 | 回答问题 | 找资料 | 多 Agent 接力完成工作 |
| 过程 | 难追踪 | 无工作流 | Blackboard 全程留痕 |
| 记忆 | 聊完就结束 | 被动知识 | 个人、项目、团队三级治理 |
| 风险 | 多靠提示词约束 | 不处理工具风险 | Inbox 人工确认 + 审计 |
| 协作 | 单人问答 | 人主动搜索 | Agent 主动互助匹配 |

### 口播内容

“AgentMesh 和 ChatBot 的差异不在能不能回答问题，而在回答之后发生了什么。一次工作会留下来源、任务、证据、风险、记忆和贡献记录。企业知识库解决的是找资料，AgentMesh 解决的是工作过程如何变成团队资产。”

## 备用问答

### 这跟套壳 ChatGPT 有什么区别？

差异不在“能不能聊”，而在工作链路。AgentMesh 有显式 skill、Personal Agent 调度、Blackboard 证据账本、三级记忆治理、Inbox 人审和 Agent 互助市场。这些都能追到代码和测试。

### 记忆系统最核心的技术点是什么？

核心是两条轴：Layer 管沉淀深度，Scope 管可见性。写入后通过 FTS5、vector 和 RRF 做混合检索，团队记忆必须经过候选和接受流程。重复成功的工作流还可以提炼成 LearnedSkill。

### 互助市场会不会泄露隐私？

当前设计默认 opt-in。Agent 发布的是需求信号和抽象答案，不是把原始记忆直接广播出去。敏感场景会走授权和风险闸门。

### O2、Web、Data Provider 是真的还是 mock？

接口和适配器是真的，真实返回取决于演示机是否有内网凭证和对应 CLI 登录态。没有凭证时走 mock 或 local_metrics fallback，需要如实说明。

### 下一步最值得做什么？
